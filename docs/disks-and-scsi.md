# ディスク、SCSI、CD-ROM

SASI のハードディスクのイメージの作り方、増設メモリ、外付け SCSI ボード、CD-ROM、ディスクの書き戻しと大きなイメージ。

## SASI のハードディスク (HDF) を作る

起動できる SASI のイメージ (HDF) は、手元の Human68k 3.02 のシステムディスクから作る (ROM もディスクのイメージも、このリポジトリには入っていない)。

```sh
python3 -I tools/make_sasi_hdf.py --size 20 ~/.cache/pix68k/disk/HUMAN302.XDF human302.hdf   # 10、20、40 (MB) を選べる
./build/x68k_boot -h human302.hdf -f 900 -o hd.ppm   # フロッピーディスクを入れずに、SASI のディスクから起動する
./build/pix68k -h human302.hdf                        # ホスト版。終わるときにファイルへ書き戻すなら --write-back
```

`make_sasi_hdf.py` は、ディスクの IPL と領域の IPL をシステムディスクの中の FORMAT.X から探して写し、フロッピーディスクの
ファイルを全部、領域の中に写す。ctest の `x68k_boot_sasi` は、こうして作ったイメージから起動し、「A>」が出ることを確かめる
(システムディスクか ROM がなければ飛ばす)。

レコード数 (10MB は 40788、20MB は 81048、40MB は 162096) と、管理情報 (ランプレコード、領域の開始と大きさ) は、FORMAT.X 2.31 が
空のイメージに書いた値を読んで合わせた (`x68k_boot -h 空のイメージ --save-hdf` の上で FORMAT.X を動かし、装置初期化と領域確保をした)。
逆に、FORMAT.X で初期化、領域確保、システムの転送をしたイメージからも起動できる (10MB、20MB、40MB で確かめた)。

SASI (`src/x68k/sasi.cpp`) と SCSI の SPC (`src/x68k/spc.cpp`) は、資料 (「Inside X68000」の SASI と SCSI の章、MB89352 のデータシート、
SCSI の規格) と、IPL ROM や Human68k を動かして見たレジスタの使い方だけから作ってある。資料で決まらず、動かした結果で決めたところ:

- SASI の割り込み (IOC のハードディスク割り込み) を出すとき: IPL ROM も Human68k も使わないので手がかりがない。ステータスフェーズに入ったときに出している
- SPC のセレクションタイムアウトのあと: IPL ROM のドライバは、TEMP に $00、転送カウンタに短い時間を書いて Time Out を消し、次の割り込みを待つ。
  転送カウンタが 0 でなければもう一度 Time Out にし、0 なら信号を戻す (MB89352 のデータシートの Select コマンドの説明のとおり)
- SPC のデータインのハード転送の終わりの割り込み: FIFO を読み終えたときに出す (IPL ROM のドライバは、割り込みが出たあとは DREG を読まない)
- 時間はかけない: セレクションも装置の処理も、レジスタを読み書きしたその場で終わる

## 増設メモリ、外付け SCSI ボード、CD-ROM

増設メモリ:

- 本体のメモリ ($000000-$BFFFFF) は `--ram MB` (ベアメタル版は `pix68k.cfg` の `ram=`) で 1MB から 12MB まで選べる。既定は 4MB。
  つないだ容量より先を読み書きするとバスエラーになる
- ハイメモリ (TS-6BE16 相当、$01000000 から 16MB) は X68030 だけ (`--cpu 68030 --high-mem 16`、`high_mem=16`)。
  68000 のアドレスバスは 24 本なので、68000 の機種では $01000000 は $000000 と同じ場所になり、ハイメモリは置けない
  (指定しても使わない)。060turbo はハイメモリの代わりにローカルメモリ ($10000000 から) を使う

外付け SCSI ボード (CZ-6BS1 相当) は、SASI の機種に SCSI をつなぐボード。$EA0001-$EA001F の奇数番地に SPC (MB89352)、
$EA0020-$EA1FFF に SCSI の ROM が見える。SPC は内蔵 SCSI と同じクラス (`src/x68k/spc.cpp`) をもう 1 つ持つ。割り込みはレベル 2、ベクタ $F6。
ボードをつながなければ、$EA0000 からはこれまでどおりバスエラーになる。

SCSI の ROM はリポジトリに入れていない。`~/.cache/pix68k/rom/SCSIEXROM.DAT` (ベアメタル版は boot パーティションの
`/pix68k/SCSIEXROM.DAT` か `/SCSIEXROM.DAT`) に置く。ファイルは $EA0000 からの 8192 バイトか、$EA0020 からの 8160 バイト。
ほかの大きさ (8192 バイトまで) は、`SCSIEX` の文字列が $EA0044 に来る位置に置く。

```sh
# 外付け SCSI ボードをつなぎ、ID 0 にハードディスク (HDS)、ID 6 に CD-ROM (ISO) をつなぐ
./build/pix68k --scsi-ex --sc 0 human.hds --cd game.iso
# 設定ファイルで指定する (pix68k.cfg と同じ形式)
./build/pix68k --config pix68k.cfg
```

- `--sc ID FILE` (`sc0=` から `sc6=`): SCSI のハードディスクのイメージ (HDS、512 バイト / ブロック)。書き込みは `--write-back` のときだけファイルに戻す
- `--cd FILE` (`cd=`): CD-ROM のイメージ。ISO (2048 バイト / セクタ) か、CUE シート (`.cue`) と、そこに書かれた BIN / WAV。
  読み出しだけ。ID は `--cd-id` (`cd_id=`、既定 6)。CD-ROM 装置は 1 台まで
- `--no-scsi-ex`: 設定ファイルの `scsi_ex=on` を打ち消し、外付け SCSI ボードをつながない
- `--cd` と `--sc` (`cd=` と `sc<N>=`) で同じ ID を指定すると、ホスト版はエラーで止まり、ベアメタル版は CD-ROM のほうをつなぐ
- つなぐ先は、外付け SCSI ボードがあればボード、なければ内蔵 SCSI (X68030 と 060turbo)。どちらもなければ、ホスト版はエラーで止まり、ベアメタル版は警告を出して無視する。ID 7 は本体が使う
- ホスト版の `--config FILE` は、ベアメタル版の `pix68k.cfg` と同じ形式のファイルを読む (キーは `src/platform/settings.h` の表。
  ファイル名の値は、`/` で始まらなければ設定ファイルのあるディレクトリから)。コマンドラインで指定したものが優先する

外付け SCSI のハードディスクから起動するには、SRAM の起動デバイスを ROM 起動、ROM 起動のアドレスを $EA0020 + ID x 4 にする
(Human68k の `SWITCH.X` の `BOOT` など)。`x68k_boot` では `--boot-rom EA0020` で同じ設定にして起動できる。

CD-ROM 装置 (`src/x68k/cd_drive.h`、コマンドは `src/x68k/spc.cpp`) は、SCSI-2 の規格 (X3T9.2/375R revision 10L) の次のコマンドに答える:
TEST UNIT READY、REZERO UNIT、REQUEST SENSE、INQUIRY (装置タイプ 5、取り外しできる媒体)、READ(6) / READ(10)、READ CAPACITY、
READ TOC (すべてのトラックとリードアウト、LBA と MSF)、READ SUB-CHANNEL (今の位置とオーディオステータス)、
MODE SENSE(6) / (10)、MODE SELECT(6) (受け取って捨てる)、START STOP UNIT、PREVENT ALLOW MEDIUM REMOVAL、SEEK、VERIFY、
PLAY AUDIO(10) / (12)、PLAY AUDIO MSF、PLAY AUDIO TRACK INDEX、PAUSE RESUME。
書き込みのコマンドは不正なコマンドとして断る。ブロックの大きさの変更、音量と出力の切り替え (MODE SELECT のページ 0Eh)、
メディアカタログ番号と ISRC はない。X68000 の CD-ROM のドライバが実際に出すコマンドは確かめていない (ドライバが手元にない)。

- PLAY AUDIO TRACK INDEX のインデックス: イメージから分かるのは 0 (プリギャップ) と 1 だけ。始まりが 0 ならプリギャップの始まりから、1 なら INDEX 01 から、2 以上なら次のトラックの始まりから鳴らす (鳴らすところがなければ、何もせずに正常に終わる)。終わりのインデックスは、0 でも 1 以上でも、終わりのトラックの終わりまで
- ハードディスクの MODE SENSE のページ: 03h (フォーマットのパラメータ) と 04h (ドライブの形)。イメージに形はないので、8 ヘッド、1 トラック 32 セクタとして、シリンダ数をブロック数から決める
- CD-ROM 装置の MODE SENSE のページ: 01h (読み出しのエラー回復)、0Dh (CD-ROM のパラメータ。1 分 = 60 秒、1 秒 = 75 フレーム)、
  0Eh (オーディオの制御。PLAY AUDIO は再生を始めたらすぐ終わる、次のトラックへ続けて再生する、音量は最大)。3Fh はこの 3 つをすべて返す
- CUE シート: `FILE` (BINARY / MOTOROLA / WAVE)、`TRACK` (AUDIO、MODE1/2048、MODE1/2352、MODE2/2336、MODE2/2352)、`INDEX`、
  `PREGAP`、`POSTGAP`、`FLAGS` を読む (`src/platform/cue_sheet.h`)。2352 バイト / セクタのデータトラックは、セクタごとにユーザデータの
  2048 バイトだけを返す。WAV は 44.1kHz、16 ビット、ステレオの PCM だけ。BIN / WAV は CUE シートと同じディレクトリから探す。
  ホスト版は `FILE` が複数の CUE シート (ISO + トラックごとの WAV など) も読む。ベアメタル版は `FILE` が 1 つの CUE シートだけ
  (複数のファイルを 1 つのイメージとして読む仕組みがない。警告を出して無視する)
- オーディオのトラックの再生: PLAY AUDIO で始め (始まりが FFFFFFFFh、PLAY AUDIO MSF では FF:FF:FF なら、今の位置から。SCSI-2 にはなく、あとの MMC の決まり)、PAUSE RESUME で一時停止と再開、START STOP UNIT (Start = 0 か LoEj)、READ、SEEK、REZERO UNIT、VERIFY で止まる。
  再生は X68000 の時間で進む (1 秒に 75 ブロック)。44.1kHz のステレオを、OPM のサンプル (62.5kHz) ごとに線形補間し、
  さらに出力のサンプリング周波数に線形補間して、1/2 にして出力のフレームに足す。MIDI の音源と同じく、X68000 の出力のフィルタ
  (直流を切るフィルタと低域通過フィルタ) は通さない (実機の CD-ROM 装置のオーディオは装置の出力から出て、X68000 の音声の回路を
  通らない)。足して 16 ビットを超えた分は、上限と下限で止める。音の合成を別のコア (`sound_core=on`) で
  行うときは、再生したフレームを X68000 を動かすコアがイメージから読んで、合成のコアに渡す (記録は、前のフレームとの差が
  14 ビットに入れば 1 フレームに 1 個、入らなければ 2 個)。大きなイメージでは使うチャンクだけを読み、
  チャンクを読み込んでいる間は再生の位置を進めずに待つ (その間は無音)。再生がデータトラックに入ると止まり、次のコマンドに
  CHECK CONDITION (BLANK CHECK) を 1 回返す
- 媒体の入れ替え: 設定メニューの CD-ROM でイメージを選ぶと、動かしたまま媒体を入れ替える (CD-ROM 装置をつないで起動したときだけ。
  `cd=` なしで起動したときは、次の起動から)。X68000 には、次のコマンドで UNIT ATTENTION (NOT READY TO READY TRANSITION,
  MEDIUM MAY HAVE CHANGED) が 1 回返る。(none) を選ぶと取り出し、媒体の要るコマンドは NOT READY (MEDIUM NOT PRESENT) になる。
  X68000 が START STOP UNIT (LoEj) でトレイを開けたときも同じで、閉じる (LoEj + Start) かメニューで入れ直すまで媒体はない。
  PREVENT ALLOW MEDIUM REMOVAL で禁止している間は、START STOP UNIT では開かない (メニューからの入れ替えは禁止していてもできる。禁止されていたことをメニューの下の行に出す)
- ステートに、トレイ、禁止、再生の状態と位置が入る (版 8 から。版 12 からは CD-ROM 装置をつないでいるときだけ)。イメージは入らないので、同じイメージをつないで読むこと
- ステートの版 12 で、SASI と SPC の状態の並びが変わった。版 11 までのステートも読める。SPC はレジスタ (BDID、SCTL、SCMD、PCTL、TEMP、転送カウンタ) だけを戻し、
  SASI と SPC のバスと転送の状態は読み飛ばして、バスフリーから始める。版 11 までのステートのうち、SCSI のコマンドの途中
  (SPC がターゲットと結合している間) で保存したものは読まない (`saved in the middle of a SCSI command by an older version`):
  コマンドの続きを戻せず、X68030 では IPL ROM のドライバが答えを待ち続けて止まる。SASI のコマンドの途中で保存したものは読める
  (その読み書きは続かないが、ドライバがやり直す)。
  前の実装で X68030 を SCSI のハードディスクから起動して保存した版 11 のステートを読み、そのあと SCSI のディスクにファイルを写せた

確かめたこと (上の 2 つは、ROM とイメージがなければ ctest では飛ばす):

- `x68k_boot_scsi_ex`: SASI の機種 (68000) で、外付け SCSI の ID 0 の HDS (`SCSI_EX_HDS`) から ROM 起動し、「A>」が出る
- `x68k_boot_scsi30_stream`: X68030 の内蔵 SCSI の ID 0 の HDS (`SCSI30_HDS`、既定 `~/.cache/pix68k/disk/HUMAN30.HDS`。なければ作らない) から、
  ベアメタル版の大きなイメージと同じチャンクのキャッシュを通して (`x68k_boot --stream`。チャンクの読み込みは最大 1 フレーム待つ) 起動し、「A>」が出る
- `x68k_scsi_ex_cdrom` (`tests/x68k/scsi_iocs.cpp`): Human68k を起動したあと、ROM の SCSI IOCS (`_S_INQUIRY`、`_S_READCAP`、
  `_S_READEXT`) で ID 6 の CD-ROM を読み、装置タイプ、容量、ブロック 16-17 の中身がイメージと合う
- `spc_test`: SPC のレジスタと転送、ハードディスクのコマンド、ボードのアドレス、ROM の置き方、割り込みのベクタ。CD-ROM のコマンドは `cdrom_test`。書き直す前のビルドが保存した古い版のステート (`tests/unit/old_scsi_state_data.h`。ROM なしの空の Machine) を読めることも確かめる
- susie.x 1.21A (GORRY さん) を `DEVICE = \SUSIE.X -ID6 *:` で組み込み、X68030 の内蔵 SCSI の CD-ROM (ISO 9660 のイメージ) を
  ドライブ C: として読めた (`DIR`、`TYPE`、150001 バイトのファイルを FD に写してホストで `cmp` して一致)。外付け SCSI ボードでは、
  ボードの ROM が手元にないので試していない
- `cdrom_test`: CUE シートの読み方、READ TOC、2352 バイト / セクタのデータトラックの読み出し、MODE SENSE のページ、媒体の入れ替えと
  取り出し、オーディオのコマンド (再生したフレームがイメージの PCM と同じ)、使うチャンクだけを読むイメージでの読み出しと再生、
  1kHz / 500Hz の正弦波を再生したときの出力 (48kHz) の実効値と周波数、10kHz の正弦波の振幅が補間だけで決まる値になる
  (出力のフィルタを通らない) こと、足して 16 ビットを超えた分が上限と下限で止まること (MIDI の音源があるときと、OPM と CD だけのとき)、
  フレーム 1 つだけを入れたときの補間の両端と止まる条件、ステートを読んだ直後 (止まっていたときと、別のところを再生していたとき) の出力、音の合成を別のコアで行うときの音が 1 つのコアのときと同じこと、
  ステートの保存と読み込み
- `sound_thread_test`: 起動、OPM、ADPCM に続けて CD-ROM のオーディオを再生し、音の合成を別のスレッドで行っても同じ音になる
- `host_cdrom` (`tests/host/cdrom_test.sh`): ホスト版 (X68030) で CUE シートをつなぎ、メニューで入れ替え、取り出し、読めない CUE シートを選ぶ
- ベアメタル版の CUE シートの読み込みとメニューでの入れ替え、実機の音は確かめていない (ビルドだけ)

ベアメタル版は、SCSI と SASI のイメージを起動のときに全体を読まず、使う 16KB のチャンクだけを SD カードから読む
(1MB 以下のイメージは全体をメモリに読む。下の「大きなイメージ」を参照)。メモリに入るイメージは、イメージ全体の大きさの
キャッシュを用意し、読んだチャンクを追い出さない。残りのチャンクは、X68000 を動かしながらコア 0 が裏で先頭から順に読む
(1 フレームに 128KB まで、1 秒に 7MB ほど。X68000 が読みたいチャンクがまだなら、それを先に読む)。読み終えるとログに
`sc0: the whole image is in memory` を出し、それからは SD カードを読まない。書き込みは、これまでと同じくメモリの上のチャンクに書いて
ファイルに書き戻す (下の「ディスクの書き戻し」。電源を切ったときに失う範囲は変わらない)。メモリの使い方:

- Raspberry Pi 4 / Raspberry Pi 5 でメモリが 1GB より多いとき: キャッシュの中身を 1GB より上のヒープ (Circle の `HEAP_HIGH`。Raspberry Pi 4 は 3GB まで、
  Pi 5 はメモリの終わりまで) に置く。空きを調べ、16MB 残して入るイメージ (4GB - 16KB まで。Circle のヒープの 1 つのブロックの上限) は全体を置く。チャンクの表など
  (64MB のイメージで 70KB ほど) は 1GB より下に置く。SD カードからは 1GB より下のバッファ (16KB) に読んでから写す
- Raspberry Pi 3 と、メモリが 1GB の Raspberry Pi 4、1GB より上に入らないとき: 1GB より下のヒープに置く。ここは Circle の `new` が使うヒープで、
  060turbo のローカルメモリ、SoundFont、MT-32 / SC-55 の ROM なども同じところから取り、足りないと全体が止まる。
  そこで確保する前に空きを調べ、32MB 残して入るときだけ全体を置く。64MB より大きいイメージは、その空きの半分までに
  収まるときだけ全体を置く
- どちらにも入らないイメージは、4MB のキャッシュ (256 チャンク) に使うチャンクだけを読む (読むコマンドの範囲と、その後ろの
  2 チャンクを先に読む)

起動のときのログの `sc0: ... (... bytes; read on demand, N KB cache above 1 GB, the rest is read in the background; ...)` で、
キャッシュの大きさ、置いたところ、全体を読むかどうかが分かる。フロッピーディスクのイメージ (1〜2MB) は、これまでどおり
入れたときに全体を読む。CD-ROM のイメージも同じキャッシュを使う。メニューで CD-ROM を入れ替えたときは、1GB より上に全体が
入ればそこに置き、入らなければ 4MB のキャッシュにする (一度作ったキャッシュは次の媒体にも使い回す)。
イメージは `sc0=` から `sc6=`、`cd=` の ID の順に読む。
読み込みの途中で失敗したときは、そのとき確保したメモリが戻らない (Circle は 512KB を超えるブロックを解放しても使い回さない) ので、
残りの SCSI のイメージは読まない。0 バイトのファイルは警告を出して飛ばし、次のイメージを読む。

## 実物のフロッピーディスクを USB-FDD から読む

USB のフロッピーディスクドライブに入れた X68000 の 2HD のディスク (1024 バイト/セクタ、8 セクタ/トラック、77 シリンダ、両面) を、
イメージのファイルを作らずにそのまま FD0 / FD1 に入れられる。ドライブが 1.2MB のディスク (3 モード) を読めることが条件で、
Y-E DATA の USB-FDU (VID:PID 057b:0000) を Pi 5 のベアメタル版につないで確かめた (ホスト版は、同じドライブを Linux の `dd` で読めることと、
読み取り専用の loop デバイスから起動できることまで。Pi 3 / Pi 4 では確かめていない)。コピープロテクトのあるディスクや、ほかの形式 (2DD、1.44MB など) は読めない。

- 起動のとき (ディスクを入れたとき) にディスクの全体 (1,261,568 バイト) をメモリに読み、XDF のイメージと同じように扱う。
  読み終えるまで 1 分ほどかかる
- **実物のディスクには書かない**。読んだイメージは書き込み禁止でドライブに入れ、書き戻しの対象にもしない。
  X68000 からは書き込み禁止のディスクに見える (セーブなどで書き込むソフトは、書き込みエラーになる)
- ホスト版 (Linux だけ): `-0 /dev/sda` のように、ブロックデバイスを渡す (2 台なら `-0 /dev/sda -1 /dev/sdb`。`usb-fdd:` はベアメタル版の
  書き方で、ホスト版では使えない。macOS などでは、実物のドライブを直接は読めない)。デバイスは読むだけで開く (`--write-back` を付けても書かない)。
  読むには権限が要る (`sudo` か、`disk` グループ)。自動でマウントされていないことを確かめ、心配なら先に
  `sudo blockdev --setro /dev/sda` で OS からも読み取り専用にしておく

  ```sh
  sudo build/pix68k --cpu 68000 --clock 10 -0 /dev/sda
  ```

- ベアメタル版: `pix68k.cfg` に `fd0 = usb-fdd:` と書く。USB-FDD が 2 台あれば、`fd0 = usb-fdd:0`、`fd1 = usb-fdd:1` のように
  0 から数えた番号を書いて、別々のドライブを割り当てられる (`usb-fdd:` は `usb-fdd:0` と同じ。`usb-fdd:3` まで)。番号は、
  **ディスクが入っていて、大きさを読めたドライブ**に、読めた順に付く (`usb-fdd:0` が Circle の `ufd1`、`usb-fdd:1` が `ufd2`、…)。
  ディスクの入っていないドライブは数に入らないので、2 台のうち 1 台目が空だと、2 台目が `usb-fdd:0` になる。
  どのポートのドライブが先になるかは、つなぎ方と、ドライブが答えるまでの時間で決まり、起動のたびに同じとは限らない
  (どのディスクがどのドライブに入ったかは、ログの `fd0: USB floppy drive 0 ...` の CRC-32 で確かめられる)。指定したドライブがないか、ディスクが入っていなければ、
  ログに `fd1: USB floppy drive 1 (ufd2) not found or no disk in it` と出して、そのドライブは空のまま起動する。
  Circle の USB-FDD のドライバ (CBI の UFI。デバイス名 `ufd1`、`ufd2`、…) を使う。
  このドライバは、USB-FDD を見つけたときにディスクの大きさを 1 回だけ読むので、**電源を入れる前にディスクを入れておく**。
  ディスクを入れずに起動したときと、起動のあとでディスクを入れ替えたときは扱えない (入れ替えたら再起動する)。
  USB の装置を探し終えてから、USB-FDD が出てくるまで長くて 10 秒待つ (2 台目は、1 台目を読み終えてから長くて 5 秒)。
  ログに `fd0: reading the disk in USB floppy drive 0`
  と進み具合が出る (Pi 5 で、読み終えるまで約 50 秒)。
  Circle のドライバは 512 バイト/セクタしか受け付けず、書き込みの命令も持っているので、ビルドのときに
  `tools/circle_ufd_patch.sh` で 1024 バイト/セクタを受け付け、書き込みを送らないように書き換えている。
  割り込みで届く 2 バイトの読み方も UFI の決まり (ASC と ASCQ) に直している (元のままだと、電源を入れた直後の
  INQUIRY を失敗と見て `ufd: Device does not respond` で止まる)。
  Pi 4 / Pi 5 の xHCI では、Circle は終わるのを待つ転送を 3 秒で打ち切るが、ドライブが読みにくいセクタを読み直す間に
  これを超えてディスクを読めなくなったことがあったので、USB-FDD への転送だけ、ドライバがドライブを調べる間と読む間は
  30 秒まで待つ (その間も、キーボードなどほかの装置への転送は 3 秒のまま)。待つ間もウォッチドッグは延ばす
  (`pix68k_deploy` のとき。Pi 3 の USB のドライバにはこの時間切れがなく、延ばすのはトラックを読むごと)。
  ドライブに送るコマンドは INQUIRY、TEST UNIT READY、REQUEST SENSE、READ CAPACITY、READ(10) だけで、
  ドライバの入口でそれ以外のコマンドと、ドライブへデータを送る要求を断っている。
  読み終えるとログに、読んだイメージの CRC-32 を出す (同じディスクをほかの方法で読んだイメージと比べられる)
- 設定メニューでリセットし直す (Restart) と、もう一度ディスクの全体を読む (読み直せなければ、そのドライブは空になる)。
  イメージを置くメモリ (約 1.2MB) は、ドライブがあって読める形式のディスクが入っていると分かってから確保し、読み直しでも使い回す
- 読めないブロックがあると、そこで止めてドライブは空のままにし、場所 (シリンダ、ヘッド、セクタ) をログに出す

### 読んだディスクをイメージに書き出す

USB-FDD から読んだディスクは、XDF のイメージ (1,261,568 バイト) として保存できる。どの方法も、実物のディスクには書かない。

- ベアメタル版の設定メニュー: 「Save FD0 image」(FD1 なら「Save FD1 image」。USB-FDD から読んだディスクが入っているドライブの分だけ出る)
  を選ぶと、読み書きしているドライブ (SD カードなど) の `/pix68k/FD-<CRC-32>.XDF` に書き出す。名前はディスクの中身の CRC-32
  (ログの `fd0: USB floppy drive 0 (..., CRC-32 602f7858 ...)` と同じ値) から決まり、たとえば `FD-602F7858.XDF` になる。
  同じディスクは同じ名前になるので、もうあれば「already saved as ...」と出して何もしない。同じ名前で大きさの違うファイルが
  あるときと、あるかどうかを確かめられなかったときも書かない (どの場合も、あるファイルを上書きしない)。
  `<名前>.new` に書き、読み戻して CRC-32 が名前と合うことを確かめてから、名前を変える (合わなければ消して、そう出す。
  書いている間に同じ名前のファイルができていたら、それは消さずに、書いたほうを消す)。
  書き出したあとは、`fd0 = FD-602F7858.XDF` と書くか、メニューの FD0 の一覧から選べば、ドライブなしで起動できる
- ベアメタル版の HTTP (`net = on`): `GET /fd0.xdf` (FD1 は `/fd1.xdf`) でイメージを取れる (`net_token=` があればトークンが要る。[network-api.md](network-api.md))

  ```sh
  curl -H 'X-Pix68k-Token: 好きな文字列' -o gradius.xdf http://pix68k/fd0.xdf
  ```

- ホスト版 (Linux): pix68k を使わずに `dd` で読める。USB-FDD が 1024 バイト/セクタのデバイスに見えていれば、そのまま XDF になる

  ```sh
  sudo blockdev --setro /dev/sda            # OS からも読み取り専用にする
  sudo dd if=/dev/sda of=gradius.xdf bs=1024 conv=noerror,sync iflag=direct
  ```

読む処理は `src/platform/real_floppy.h` にまとめてあり、ドライブごとの違いは `RealFloppySource` (ブロックを読む関数だけを持つ)
に分けてある。FDC 互換のドライブ (TNB製作所の「ふろっぴU君」など) を足すときは、これを実装する。

## ディスクの書き戻しと大きなイメージ (ベアメタル版)

X68000 がフロッピーディスクとハードディスク (SASI、SCSI) に書いた内容は、SD カードのイメージのファイルに書き戻す (`write_back=on`、既定)。
`write_back=off` にすると書き込みはメモリの上だけで、電源を切ると消える (前の版と同じ)。

- 書く時期: 書き込みが 2 秒止んだとき (書き続けていても 30 秒ごと)。ほかに、フロッピーディスクの入れ替えと取り出し、
  設定メニューの Reset、Restart、Save settings、Save state のとき。設定メニューを開いている間 (X68000 は止まっている) は、
  書いていない分を待たずに書く。フロッピーディスクを入れ替えるときは、新しいイメージを読む前に今のディスクを書く
  (同じファイルを入れ直しても、書き戻す前の古い内容を読まない)。書き終えるとログに `fd0: image file replaced` や `hd0: written back` を出す
- コア 1 (X68000) は SD カードに触らない。コントローラは書いたバイトの 16KB のチャンクの dirty フラグを立てるだけで、コア 1 はフレームの切れ目で
  dirty フラグの立ったチャンクを 1 フレームに 64KB まで受け渡しのバッファに写し、コア 0 が FatFs で書く (`src/platform/disk_sync.h`)
- 書き方: ハードディスクはファイルの中の書いたチャンクだけを上書きし、まとめて `f_sync` する。数百 MB のファイルを毎回書き直すわけには
  いかないので上書きにする。途中で電源が切れると、そのとき書いていたチャンク (多くて 64KB) は古い中身と新しい中身が混じることがある
  (本物のハードディスクで書いている途中に電源を切ったのと同じ)。ファイルの大きさとクラスタの並びは変えないので、FAT は壊れない。
  フロッピーディスク (1〜2MB) は全体を `<名前>.new` に書いてから元のファイルと置き換える (SRAM や pix68k.cfg と同じ手順。
  `src/platform/file_replace.h`)。途中で電源が切れても、前の内容か新しい内容のどちらかが残る
- 書けなかったとき: 書けなかった分は受け渡しのバッファ (フロッピーディスクはコア 0 の写し) に残し、1 秒から 30 秒まで間を延ばしながら
  書き直す (待つ間と続けて失敗した回数はディスクごとに持ち、書けないディスクがあっても、ほかのディスクのチャンクは書く。ただし受け渡しのバッファは 1 つなので、書けないディスクのチャンクが残っている間は、ほかのディスクの次のチャンクは写せない)。ハードディスクのファイルは開き直してから書き直す (FatFs は読み書きのエラーを開いたファイルに残し、
  そのファイルの以後の読み書きがすべて失敗するため)。書けないままのフロッピーディスクは取り出さず、Restart もしない (メニューに理由を出す)。
  SD カードに空きがないときなどに抜けられるよう、ほかの操作をはさまずに続けてもう一度同じ取り出し (同じドライブの一覧の [Eject]) か Restart を選ぶと、書き戻さずに取り出す / 再起動する
  (書けなかった内容は消える)。`tools/deploy_pi.sh` で起動したときの終わりの再起動 (`pix68k_deploy=秒数`) も、書けるまで X68000 を止めたまま
  1 秒ごとに書き直す。その間の入力は捨てる。メニューは開ける (閉じても X68000 は止めたまま)。書ければそのまま再起動し、メニューの Restart を 2 回選べば
  書き戻さずに再起動する
- ステートの読み込みは X68000 のメモリと周辺機器の状態だけを戻し、ディスクのイメージは戻さない (保存したあとに書いた内容は、ファイルに書き戻した
  ままになる)。ステートを保存したときと同じ中身のディスクで読み込む
- 書き込み禁止: ファイルの読み取り専用の属性、D88 のヘッダの書き込み禁止、`write_protect=fd1,sc0` (fd0 fd1 hd0 sc0〜sc6 を並べる) で
  書き込み禁止にする。同じファイルを 2 台のドライブに入れたときは、2 台目を書き込み禁止にする。CD-ROM は書かない
- 既定を `on` にした理由: SD カードの書き込みの回数より、X68000 で保存したものが電源を切ると黙って消えるほうが困るため。
  書き込みが止んでからまとめて書くので、書く回数は X68000 の書き込みの回数より少ない

ハードディスクと CD-ROM のイメージ (1MB を超えるもの。FAT32 の上限の 4GB まで) は、使う 16KB のチャンクだけをキャッシュに読む
(`src/x68k/disk_cache.h`)。キャッシュは、メモリに入るイメージならイメージ全体の大きさ (残りのチャンクは裏で読む)、
全体の大きさのキャッシュ (管理領域を含む) が入らないイメージは 4MB (入るかどうかの決め方は、上の「メモリの使い方」)。
以前は 64MB 以下のイメージを起動のときに全体を読んでいたが、SASI の 20MB のイメージで QEMU で 2.7 秒かかったので、起動を待たせないようにチャンクだけを読むようにした。コア 1 は SD カードを読めないので、まだ読んでいないチャンクに来ると、コントローラは REQ を出さず
(SPC は FIFO を空 / 一杯にし、DMAC にも要求を出さずに) コア 0 が読み終えるまで待つ。読み書きの範囲のチャンクと、その後ろの 2 チャンクは
コマンドを受けた時点で先に頼む。書いたチャンクは書き戻すまでキャッシュから追い出さない。読めなかったチャンクはエラーのステータス
(SASI はセンス 0x11、SCSI は MEDIUM ERROR) にする。FatFs は fast seek (`FF_USE_FASTSEEK`) を有効にしてビルドし
(`tools/build_baremetal.sh` が Circle の写しの `ffconf.h` を書き換える)、ファイルの中の位置を変えるときに FAT をたどらない。
`write_back=off` のときは、書いた内容をメモリに残すため、ヒープに入るイメージは起動のときに全体を読む。入らないイメージは書き込み禁止にする。
SASI の FORMAT DRIVE / FORMAT BLOCK も同じキャッシュを通して行い、まだ読んでいないチャンクに来ると、REQ を出さずに BSY のまま
コア 0 が読み終えるまで待つ (0 にしたチャンクは書き戻すまで追い出さないので、4MB のキャッシュでは書き戻しながら進む)。速さのログと一緒に、読んだチャンクの数と時間を出す
(`disks: N chunk reads (avg U us, max M us)`)。

SD カードの速さの見積もり: Pi 3 の Raspberry Pi OS で測ると、16KB のランダムな読み込みが 1 回 1.06ms (15MB/s)、順の読み込みが 15〜20MB/s だった
(Circle の SD のドライバの速さは実機で未確認)。X68000 の SCSI のハードディスクはシークに十数 ms かかり、転送は速くても 1〜2MB/s なので、
チャンクを待つ時間は本物のドライブより短いと見ている。

ハードディスクの DMA の転送 (DMAC のチャネル 1。内蔵 SCSI の ROM は SPC の DREG をオートリクエストで 256 バイトずつ、
SASI の IOCS はデータのレジスタを外部要求で読む) は、X68000 の時間を使わない。060turbo の速さで大きなファイルを読むと
1 フレームに 50 万バイトほどを転送し、1 バイトずつ転送すると、その時間でフレームが遅れた (Pi 5 で最悪 51ms。SD カードの
読み込みを待つ時間ではない)。そこで、デバイスから RAM への転送は、1 バイトずつ転送したときと結果 (メモリ、SPC / SASI の
状態、DMAC のレジスタ) が同じになる分だけをまとめて写す (`Spc::readData()`、`Sasi::readData()`、`Machine::dmaBlockToRam()`。
フロッピーディスクの読み込みと同じ仕組み)。X68000 から見た結果と時間は変わらない。RAM からデバイスへの転送 (書き込み) は
1 バイトずつのまま。`spc_test` と `sasi_test` で、まとめた転送と 1 バイトずつの転送の結果が同じことを確かめる。

ctest で使う ROM とイメージの場所は、CMake の `SCSI_EX_ROM` (既定 `~/.cache/pix68k/rom/SCSIEXROM.DAT`) と
`SCSI_EX_HDS` (既定 `~/.cache/pix68k/disk/HUMAN302.HDS`) で変えられる。
