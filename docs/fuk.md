# FUK (ふろっぴU君) を使う

TNB製作所の「ふろっぴU君」は、X68000 の FDC (μPD72065) と FDD を USB でエミュレータにつなぐ装置です。この文書とソースでは FUK と呼びます。pix68k は、内蔵の FDC のエミュレーションの代わりに FUK を使えます (#295)。

確かめたのは、FUK の動作を再現する Pico 2 W のファーム (ディスクは、ファームと一緒に書き込んだ 2HD のイメージ 1 枚) です。ふろっぴU君の実物では、まだ動かしていません。確かめた範囲は、終わりの「試験」と「実物のふろっぴU君で確かめていないこと」に書きました。

## 使い方

### ベアメタル版 (Pi 4、Pi 400、Pi 5)

`pix68k.cfg` に次の行を書き、FUK を Pi の USB につないで起動します。

```
fuk=on
```

- 起動のときに FUK (USB の VID:PID が 04D8:E6B1 で、シリアルポートを 2 本持つ装置) を探します。見つかれば、ログに `FUK connected` と出ます。
- 見つからなければ、警告をログに出して、内蔵の FDC のまま起動します (`fd0=` と `fd1=` のイメージが使えます)。あとからつないでも使いません。つないでから再起動してください。
- 使い始めたあとに抜くと、FDC のコマンドは「ノットレディ」で異常終了します。挿し直せば、また使えます。
- Pi 2 と Pi 3 では使えません (`fuk=on` を書いても、警告を出して内蔵の FDC を使います)。Pi 2 と Pi 3 の USB のコントローラは、同じ装置への受信と送信を同時に進められないためです。

### ホスト版 (Linux、macOS、Windows)

```
pix68k -r ~/x68k --fuk on                                          # Linux、Windows
pix68k -r ~/x68k --fuk /dev/cu.usbmodem101,/dev/cu.usbmodem103     # macOS
pix68k -r ~/x68k --fuk COM3,COM4                                   # Windows (ポートを名前で書くとき)
```

- `on` は Linux と Windows だけです。Linux では `/dev/serial/by-id/usb-TNB_Factory._FDC_emulator-if00` と `-if02` を開きます。Windows では、FUK の 2 本のシリアルポートは COM ポートに見えるので、USB の VID:PID (04D8:E6B1) とインタフェースの番号 (0 と 2) から COM ポートを探して開きます (ドライバは Windows の標準の usbser.sys)。
- macOS では、2 本のシリアルポートの名前を `,` で区切って書きます。Windows でも `COM3,COM4` のように書けます。順番はどちらでもかまいません。
- 名前を書いていないポートには、何も送りません。
- 設定ファイルの `fuk=` にも同じ値を書けます。
- 環境変数 `PIX68K_FUK_TRACE` を設定すると、送受信したバイトを時刻付きで標準エラーに出します (調べるとき用)。

### ディスクを XDF のイメージに読み出す

FUK につないだ FDD のディスクを、XDF のイメージ (1,261,568 バイト) にできます。読めるのは 2HD (77 シリンダ、2 面、8 セクタ、1 セクタ 1024 バイト) のディスクだけです。ディスクには何も書きません。それでも、大事なディスクは書き込み禁止にしてから入れてください。

ホスト版は、X68000 を動かさずに読み出して終わります (ROM は要りません)。

```
pix68k --fuk on --fuk-read 0 disk.xdf                                        # Linux
pix68k --fuk /dev/cu.usbmodem101,/dev/cu.usbmodem103 --fuk-read 0 disk.xdf   # macOS
pix68k --fuk on --fuk-read 0 disk.xdf                                        # Windows
```

`0` は FUK のドライブの番号 (0〜3) です。

ベアメタル版 (Pi 4、Pi 400、Pi 5 で `fuk=on`) は、ネットワークから頼みます ([network-api.md](network-api.md)。書き込みと同じ許可 (`net_allow=` か `net_token=`) が要ります)。

```
pix68kcli fuk-read --drive 0 disk.xdf
```

curl で頼むときは、次のようにします。

```
curl -H 'X-Pix68k-Token: 好きな文字列' -X POST 'http://pix68k/fuk/read?drive=0'
curl http://pix68k/fuk/status          # state=done になるまで待つ
curl -f -H 'X-Pix68k-Token: 好きな文字列' -o disk.xdf http://pix68k/fuk.xdf
```

- ベアメタル版では、読んでいる間 X68000 が止まります (画面の左上に表示が出ます。キーなどの入力は捨てます)。終わると続きから動きます。X68000 がフロッピーディスクを読み書きしている途中なら、すぐに断り、X68000 の操作はそのまま続きます。pix68kcli は 1 秒おきに 5 回まで頼み直します。curl では、少し待ってから頼み直してください。読み出している間に再起動を頼むと、読み出しをやめてから再起動します。
- 読めないセクタがあると、3 回まで読み直し、それでもだめなら 1 セクタずつ読み直します。どうしても読めなければ、位置 (シリンダ、面、セクタ) と FDC の結果を出して失敗します。欠けたイメージは作りません。
- ディスクの出し入れ、FUK の抜き差し、X68000 のリセットがあれば、失敗で終わります。やめるときは Ctrl+C (ホスト版と pix68kcli) か `POST /fuk/cancel` です。
- pix68kcli とホスト版は、すでにあるファイルを上書きしません。
- 各トラックの 9 番目より後ろのセクタは見ません。書式が違うディスク (2DD、セクタの大きさが違うもの、一部の市販ソフトのディスク) は、失敗するか、8 番目までしか読めません。D88 にはできません。

### 使っている間の制限

- 内蔵の FDC は使いません。`fd0=`、`fd1=` (ホスト版は `-0`、`-1`) のイメージと、設定メニューでのディスクの入れ替えは、X68000 からは見えません。
- ステートは保存も読み込みもできません。USB の先にある FDC の状態は保存できないためです。
- 速さは FUK で決まります。
- DMA を使わない書き込みはできません。Write のコマンドの 1 バイト目が来たときに、DMAC のチャネル 0 が動いていない (開始していない、異常終了したあと) か、転送バイト数が 0 か、SPECIFY の ND が 1 なら、DMA を使わない書き込みとみなします。DMAC がアレイチェーン、リンクチェーン、コンティニューで動いているときの書き込みも受け付けません (FUK に先に知らせるバイト数が、最初のブロックの分しか分からないため)。FUK には送らず、異常終了 (ST0 = `0x40 | ユニット`、ST1 = オーバーラン) を返します。X68000 の IOCS と Human68k は DMA で書くので、ふつうは当たりません。DMA を使わない読み出しはできます。
- 書き込みは、そのまま FUK のディスクに書かれます。次のときは DMAC からデータが全部そろわないので、FUK にデータを送る前に書き込みをやめ、FUK の FDC をリセットして、X68000 にはオーバーランの異常終了を返します (USB が切れたときの制限は、下の「既知の制限」に書きました)。
  - FUK がデータを求めてから 1 秒たっても、DMAC が残りを渡してこないとき
  - DMA が途中で異常終了したとき (バスエラー、ソフトウェアアボート。FUK がデータを求める前に異常終了していたときも)
  - DMAC が、先に知らせたバイト数より少ないところで転送を終えたとき

  Pico 2 W のファームは、リセットでデータを待つのをやめます。実物のふろっぴU君がやめるかは確かめていません。やめない場合、次の書き込みで送る `'M'` とデータが、やめたはずの書き込みのセクタに書かれます。同じセクタの再試行なら害はありませんが、別のセクタへの書き込みなら、そのセクタを壊します。

## FUK とのやり取り

FUK は USB のシリアルポート (CDC) を 2 本持ちます。

| ポート | 役割 |
|---|---|
| ポート 1 | レジスタの読み書き |
| ポート 2 | 割り込みの通知と、Read / Write のデータ |

どちらがポート 1 かは決まっていないので、両方に `0x00` を送って見分けます。`'f'` を返したほうがポート 1、`'F'` を返したほうがポート 2 です。見分けたら、ポート 1 に `0x80 0xFE` (初期化) と `0x40` (リセット) を送ります。

ポート 1 (pix68k → FUK):

| 送るバイト | 意味 | 返事 |
|---|---|---|
| `0x80\|reg`, 値 | レジスタ reg に書く | なし |
| `reg` (bit7 が 0) | レジスタ reg を読む | 1 バイト |
| `0x40` | FDC のリセット | なし |

| X68000 のアドレスなど | reg |
|---|---|
| `$E94001` FDC のステータス | `0x01` |
| `$E94003` FDC のデータ (コマンド、リザルト) | `0x03` |
| `$E94005` ドライブ制御 / ドライブの状態 | `0x05` |
| `$E94007` ドライブ選択 | `0x07` |
| `$E9C001`〜`$E9C00F` I/O 割り込み | `0x10 \| (アドレス & 0x0F)` |
| FDD の強制レディ (OPM の CT) | `0x23` (bit6) |
| DMAC チャネル 0 の転送バイト数 (Write の前に書く) | `0x30` (下位)、`0x31` (上位) |

ポート 2 (FUK → pix68k):

| バイト | 意味 |
|---|---|
| `'C'` / `'c'` | FDC の割り込みが立った / 下りた |
| `'D'` / `'d'` | FDD の割り込み (ディスクの出し入れ) が立った / 下りた |
| `'R'`, 長さ (2 バイト、下位が先), データ, リザルト 7 バイト | Read の結果。長さはデータとリザルトを合わせたバイト数 |
| `'W'` | 書くデータを求めている |
| `'w'` | 書き込みが終わった |
| `'t'` | 中止 |

ポート 2 (pix68k → FUK): `'M'` に続けて、先に知らせた転送バイト数ぶんのデータを送ります。

`Machine::setFuk()` で `Fuk` を渡すと、`$E94001`〜`$E94007` の読み書き、DMAC のチャネル 0 の要求と終了、FDC と FDD の割り込み、強制レディ、`$E9C001`〜 への書き込み、リセットが `Fuk` に向きます。

### USB の往復で X68000 を止めない

ポート 1 の読み出しは、返事が届くまで 1 ms ほどかかります。そのたびに X68000 を動かすスレッド (ベアメタル版ではコア 1) を止めると、ディスクを読んでいる間の音や画面が遅れます。そこで、X68000 が読む値を `Fuk` が先に読んでおきます。

- **リザルト (`$E94003`)**: コマンドを送ったあとに、`Fuk` がリザルトの読み出しを順に送ります。そろうまで、X68000 にはステータス `0x10` (ビジー、RQM なし) を返します。そろったら `0xD0` にして、`$E94003` の読み出しには手元の値を返します。ソフトウェアは RQM を待ってから読むので、応答の遅い FDC に見えるだけです。
  - SENSE INTERRUPT STATUS は ST0 を読み、ST0 が `0x80` (引き取る割り込みがない) でなければ PCN も読みます。SENSE DEVICE STATUS は 1 バイトです。
  - Write (WRITE DATA、WRITE DELETED DATA、WRITE ID、SCAN) は、`'w'` が届いてから 7 バイト読みます。
  - READ ID は、ステータスを 2 ms ごとに読んで、リザルトが用意できた (`0xD0`) と分かってから 7 バイト読みます。
  - 上のどれでもないコマンドは、リザルトがあるか分からないので、ステータスを見ながら 1 バイトずつ読みます。
- **ステータス (`$E94001`)**: コマンドのバイトを受け取っている途中 (`0x90`)、FUK の答えを待っている間 (`0x10`)、リザルトを返している間 (`0xD0`) は、状態から作ります。コマンドを待っているときは、最後に FUK から読んだ値を返します。その値が 20 ms より古ければ、返しつつ読み出しを 1 つ送って更新します。コマンドを送った直後や `'C'` が届いた直後は、最後に読んだ値が使えないので、新しい値が届くまで `0x10` を返します。
- **ドライブの状態 (`$E94005`)**: ドライブ制御を書いたときに、状態の読み出しも送ります。値は、選んだドライブの組ごとに覚えます。覚えた値が 50 ms より古ければ、返しつつ読み直します。`'D'` が届いたときと、排出を書いたときは、覚えた値を捨てます。
- **I/O 割り込みの状態 (`$E9C001`)**: FDC と FDD のビットは、ポート 2 の `'C'` `'c'` `'D'` `'d'` から作ります。FUK には読みに行きません。

読み出しは 1 つずつ送り、返事が届いてから次を送ります (返事は送った順にしか来ないため)。書き込みは返事を待ちませんが、読み出しの返事を待っている間は、順番を保つために一緒に待たせます (256 個まで並べます)。待たせている書き込みが 224 個を超えたら、空くまで X68000 を待たせます (長くて 30 ms)。それでも空かなければ、待ち直さずに、返事が来ないときと同じく、見分けからやり直します。書き込みを 1 つでも落とすと、FUK と状態がずれるためです。

X68000 を待たせるのは、上に書いた書き込みがたまったときと、次の「少しだけ待つ」のほかは、先に読んでいない値を読まれたときだけです。

- ドライブの組を初めて選んだ直後と、`'D'` のあとの最初の `$E94005` の読み出し
- リザルトがそろう前に、ステータスを見ずに `$E94003` を読んだとき
- コマンドを待っているのに `$E94003` を読まれ、FUK にリザルトが残っているかもしれないとき

待つのは長くて 30 ms で、届かなければ手元の値か 0 を返します。

Pico 2 W のファームを Pi 5 (Linux) のホスト版につないで測った値 (2026-11-22、Human68k 3.02 を起動して `dir` まで):

| 項目 | 値 |
|---|---|
| ポート 1 の読み出し | 1077 回 |
| 往復の時間 (読み出しを送ってから返事を受け取るまで) | 最小 0.08 ms、中央 0.56 ms、90% が 0.91 ms 以下 |
| X68000 を待たせた回数 | 4 回、合わせて 1.9 ms |
| 時間切れ | 0 回 |

往復の時間には、返事が届いてから pix68k が次に見に行くまでの時間も入ります。ホスト版もベアメタル版も、1 フレーム分を実時間より速く動かし終えると、次のフレームの時刻まで休みます。その間に届いた返事は、次のフレームで受け取ります (測った最大は 16 ms)。

### ステータスを読んで待っているときは、少しだけ待つ

ベアメタル版の Pi 5 では、X68000 の 1 フレーム分を 2 ms ほどで動かし終え、残りの 16 ms は休みます。ソフトウェアがステータスを読みながら返事を待っていても、返事 (1 ms ほどで届く) の前にそのフレームを動かし終えてしまい、読み出し 1 回が平均 5 ms かかりました。

そこで、ポート 1 の返事を待っている間にステータスを読まれたときは、0.2 ms だけ受信を待ってから答えます (`yieldForReply()`。macOS のホスト版は 1 ms 単位でしか待てないので、届かなければ 1 ms ほど待ちます)。16 ms の間に待った時間の合計が 2 ms に達したら、その 16 ms の残りは待ちません (X68000 が実時間に追いつけなくならないように。最後の 1 回の分だけ 2 ms を超えることがあります)。これで、Pi 5 で起動から 10 秒の間に進む読み出しが 577 回から 733 回に増えました。

Pi 5 のベアメタル版で測った値 (2026-11-22、68000 の 16MHz、Human68k 3.02 を起動して `dir` まで): 読み出し 1098 回、X68000 の速さ 100%、待たせた回数 4 回 (合わせて 4.1 ms)、上の短い待ちは合わせて 0.55 秒 (24 秒のうち)、時間切れ 0 回、送信の失敗 0 回、受信の取りこぼし 0 バイト。

### Read と Write のデータ

内蔵の FDC と同じく、DMAC のチャネル 0 のエミュレーションが `$E94003` を読み書きしてデータを運びます。DMAC のレジスタ (MAR、MTC、CSR) と割り込みは、実機と同じように変わります。

- **Read**: `'R'` のデータが届き始めたら DMAC に要求を出し、届いた分だけを渡します。DMAC の転送バイト数 (MTC) は、FUK からデータが届くのに合わせて減ります。DMAC が転送バイト数ぶんを読み終える (TC) と、DMAC の COC はその時点で立ちます。FDC のリザルトと割り込みは、`'R'` の残りと最後の 7 バイト (リザルト) が届いてから出します。TC の前に届いたデータを渡し終えたときも、リザルトが届いた時点で出します。詳しくは次の「Read のデータを渡す時刻」に書きました。
- **Write**: コマンドの 1 バイト目が来たときの DMAC の転送バイト数を、`0xB0` と `0xB1` で FUK に知らせます。`'W'` が届いたら DMAC に要求を出し、受け取ったデータを `'M'` に続けて送ります。`'w'` が届いたらリザルトを読み、割り込みを立てます。
- Read で DMAC を使わないとき (SPECIFY の ND が 1 か、コマンドを受け取ったときの転送バイト数が 0) は、ステータスを `0xF0` にして、CPU が `$E94003` を 1 バイトずつ読みます。
- Write で DMAC を使わないときは、コマンドを FUK に送らず、異常終了にします。書くバイト数を DMAC の転送バイト数から取るので、DMAC を使わないと数が分からず、0 バイトや前の転送の残りの数を知らせて、データなしで実物のディスクに書かせてしまうためです。
- `'M'` とデータは、送り始めたら最後まで送ります (装置が USB から消えて戻ったときを除きます。この段落の後半)。途中で X68000 がリセットされても、時間切れでつなぎ直しになっても、送り切ってからリセット (`0x40`) や見分け (`0x00`) を送ります。「送り切った」は、ポートに渡したバイトが装置へ出ていったこと (ベアメタル版はリングが空で USB の転送が終わっている、ホスト版は OS の送信のバッファが空。OS が残りを答えないときは空とみなします) を見たうえで、FUK から `'w'` (書き込みの終わり) が届いたことで決めます。口から出ていっても装置の中のバッファに残っていることがあり、装置がポート 1 を先に読むと、リセットのあとに残りのデータが通知用の入力として読まれるためです。`'w'` の代わりに `'t'` (中止) が来たときと、データが出ていってから `WRITE_TIMEOUT_US` (10 秒) たっても `'w'` が来ないとき (装置が止まっているとみなす) は、待たずに先に進みます。口が「同じ装置との通信が一度切れて戻った」と知らせたとき (つなぎ直しの番号が変わらない) も、送り残しは捨てずに続きを送ります。送り残しを捨てるのは、装置が USB からいったん消えて戻ったとき (つなぎ直しの番号が変わったとき) です。ベアメタル版は USB の転送が失敗した装置を、ホスト版は読み書きに失敗したシリアルポートを、装置が USB から消えるまで使いません (ホスト版は、2 本のポートのどちらかの名前がいったん見えなくなったのを見てから開き直します)。消えて戻った装置は初めの状態に戻ったとみなしますが、そうでない場合があります (下の「既知の制限」)。送り切れない間は、見分けに進まずに待ちます (X68000 には、つながっていないときと同じに答えます)。
- FUK が `'W'` でデータを求めたあと、`'M'` を送り始める前 (DMAC からデータを受け取っている途中) に X68000 がリセットされたときは、`'M'` を送らずにリセット (`0x40`) を送ります。そろっていないデータを 0 で埋めて送ると、それがディスクに書かれるためです。Pico 2 W のファームは、リセットで `'M'` を待つのをやめます (`fdc.c` の `reset()` が、コマンドの段階に戻して `'M'` 待ちを解く)。実物のふろっぴU君がリセットで待ちをやめるかは確かめていません。残りを送らないと、FUK はそのあとポート 2 に届いたバイトをデータとして読むためです (Pico 2 W のファームのソースで確かめました)。
- Read の割り込みは pix68k が作ったもので、FUK には引き取る割り込みがありません。Read のあとの SENSE INTERRUPT STATUS は FUK に送らず、ST0 = `0x80` を返します (シークの終わりを引き取っていないドライブがあるときと、`'C'` が立っているときは送ります)。

### Read のデータを渡す時刻 (#320)

pix68k は、FUK からバイトが届いた時刻の間隔を、そのまま X68000 の時間に写して DMAC に渡します。

- X68000 は 1 フレーム分 (16.7 ms) をまとめて実時間より速く動かしてから休みます。休んでいる間に届いたバイトを届いた順にそのまま渡すと、次のフレームの初めにまとめて渡ることになり、最初のバイトから COC までの長さがフレームの単位に丸められます。
- そこで、受信した時刻 (ホスト版はシリアルポートを読むスレッドが受け取った時刻、ベアメタル版は USB の受信の転送が終わった時刻) を、`'R'` のデータの 1 バイトごとに覚えます。i バイト目は、X68000 の時間で「最初のバイトを受け取った時刻 + 遅れ L + (i バイト目が届いた時刻 - 最初のバイトが届いた時刻)」に渡します。間隔を伸ばしたり、詰めたり、均したりはしません。
- L は、まだ届いていないバイトの渡す時刻が、届くより前にならないための遅れです。X68000 が実時間より先に進むのは多くて 1 フレームなので、L の上限は「1 フレーム + その 1/8」(60 Hz の画面で 18.8 ms) から、最初のバイトが届いてから受け取るまでにたった時間を引いたものです。1 フレームの長さは、X68000 の画面のその時の設定から求めます。1/8 は、受け取りの遅れやフレームの揺れのための余裕です。
- `'R'` が上限より前に全部届いたら、すべての届いた時刻が分かっているので、そこで L を決めて渡し始めます。
- L は Read 1 回ごとに 1 回だけかかります。`pix68k.cfg` の `fuk_lead=` (マイクロ秒、0〜200000) で決まった値にできます。決めたときは、上の上限や `'R'` が全部届いたかによらず、いつもその遅れで渡し始めます。0 (既定) は上の求め方です。
- DMAC の転送バイト数は渡した分だけ減り、1024 バイト目を渡したときに TC になって COC が立ちます。
- TC のあとも、`'R'` の残り (EOT までのセクタ) とリザルトは受け取ります。FDC のリザルトと割り込みは、リザルトが届いてから出します。
- データが届いている途中で DMA が異常終了したときも、リザルトが届くのを待ってから、オーバーランの異常終了にします。
- 届いている途中で残りが来なくなったら、`READ_TIMEOUT_US` (3 秒) で時間切れにします。
- DMA を使わない Read (CPU が `$E94003` を 1 バイトずつ読む) は、今までどおり全部届いてから渡します。

この写し方は、届いた時刻の間隔を保つだけです。偽物の装置で確かめました。実物では確かめていません。

かかる時間: Read 1 回ごとに、渡し始めが L だけ遅れます。測った L の平均は、Pi 4 のベアメタル版が 5.1 ms、Mac のホスト版の試験 (x68k_boot と hostsim) が 2.9 ms でした。Human68k の起動と `copy` (320 回) では合わせて 0.83 秒でした。#320 の前も `'R'` が全部届くのを待ってから渡していたので、L のうちその待ちに当たる分は増えていません。一方、X68000 が休んでいる間に `'R'` が全部届いた場合、#320 の前はすぐに渡していましたが、今は L がほぼ 0 でも、届いた間隔 (8 KB なら 8 ms ほど) を X68000 の時間でなぞってから渡し終えます。この分は L の合計に入っていません。

ホストが実時間に合わせて X68000 を動かせないと、バイトが渡す時刻に間に合わなくなります (`fuk:` の行の `late` に、渡す時刻より 64 µs を超えて遅れて届いたバイトがあった Read の回数と、最大の遅れが出ます)。Mac で x68k_boot を試したとき、15 ms 眠ると 120 ms ほどあとに戻ることがあり、X68000 が実時間より遅れてから速く動いて追いつく間に、バイトが最大で 100 ms 遅れました。x68k_boot の `--fuk-ports` は、眠らずに回って待ちます。ホスト版の本体は、FUK を使う間だけ、待ちの最後の 2 ms を回って待ち、`SDL_Delay()` が一度でも 1 ms を超えて寝過ごしたら、そのあとは眠らずに回って待ちます (標準エラーに `fuk: SDL_Delay(...) took ...` と出ます)。終了するときの `fuk:` の行に、渡した Read の数、L の合計、late の数と最大の遅れ、届いた時刻を覚えるリングが一杯で覚えられなかったまとまりの数を出します。

### 強制レディ

強制レディが立ったときは、覚えておくだけで送りません。そのあと RECALIBRATE が来たら、その直前に `0xA3 0x40` を送ります。下りたときは、送っていた場合だけ `0xA3 0x00` を送ります。

### リセット

X68000 をリセットすると、ポート 1 に `0x40` を送ります。続けてステータスを 1 回読み、その返事が届いてからポート 2 に 10 ms 何も届かなくなるまで、ポート 2 に届いたものを捨てます (リセットの前の `'R'` の残りを、通知と取り違えないため)。その間に X68000 が出したコマンドは、ためておいてあとで送ります。

### つながっていない間

抜いたとき、見分けに失敗したとき、時間切れのあとつなぎ直している間は、ドライブが 1 台もレディにならない FDC として答えます。

- Read、Write、READ ID: ST0 = `0x48 | ユニット` (異常終了、ノットレディ) のリザルトと割り込み
- SEEK、RECALIBRATE: 割り込みを立て、SENSE INTERRUPT STATUS に ST0 = `0x68 | ユニット` を返す
- SENSE DEVICE STATUS: レディでない ST3
- ドライブの状態: ディスクなし

実行中だったコマンドも、同じ異常終了で終わらせます。SEEK と RECALIBRATE を送って終わりの通知を待っていたドライブには、異常終了 (ノットレディ) のシークの終わりと割り込みを作ります (X68000 が割り込みを待ち続けないように)。これは、つながり直したあとでも SENSE INTERRUPT STATUS で引き取れます。

### 時間

時間はすべて実時間で数えます。相手が実物の装置で、X68000 の速さ (最高速モードなど) と関係なく動くためです。

| 定数 (`Fuk::`) | 値 | 理由 |
|---|---|---|
| `MSR_FRESH_US` | 20 ms | コマンドを待っている間のステータスが変わるのは、コマンドを送ったときと `'C'` が届いたときで、どちらもそのときに読み直す。これは通知を取りこぼしたときの備えで、古くなったための読み直しは 1 秒に 50 回ほど (コマンドや `'C'` のあとの読み直しは別) |
| `DRIVE_FRESH_US` | 50 ms | ディスクの出し入れは `'D'` で届く。これも備えで、ディスクを待って読み続けるソフトウェアが、読み直しの返事が届いたあとの読み出しで新しい値を受け取れる |
| `YIELD_STEP_US`、`YIELD_BUDGET_US`、`YIELD_WINDOW_US` | 0.2 ms、2 ms、16 ms | 上の「少しだけ待つ」の、1 回に頼む長さと、1 フレームほどの時間あたりの目安 (合計がこれに達したら待たない)。X68000 の時間の 1/8 |
| `WAIT_US` | 30 ms | 往復 (測った値で 1 ms 以下) の 30 倍。Pico のファームはフラッシュを書く間に返事が遅れることがある。届かなくても、目安として 2 フレーム以内に X68000 に戻る |
| `REPLY_TIMEOUT_US` | 0.5 秒 | ポート 1 の返事が来ないと決める時間。フラッシュの消去 (数十 ms) より十分長い |
| `READ_TIMEOUT_US` | 3 秒 | `'R'` が来ないと決める時間。モーターが回り始めてからディスクが 2 回転して読み終えるまでより長い |
| `WRITE_TIMEOUT_US` | 10 秒 | `'W'` や `'w'` が来ないと決める時間。1 トラックの書き込みより十分長く、フォーマットでも足りる |
| `DMA_TIMEOUT_US` | 1 秒 | `'W'` のあと、DMAC がデータを渡してこないと決める時間。書き込みをやめて FUK の FDC をリセットし、リザルトをオーバーランにする |
| `RESULT_TIMEOUT_US` | 3 秒 | READ ID などのリザルトが用意されないと決める時間 |
| `SETTLE_QUIET_US` | 10 ms | リセットのあと、ポート 2 が静かになったとみなす時間。USB のフレーム (1 ms) の 10 倍 |
| `DRAIN_QUIET_US` | 30 ms | 見分ける前に、受信が空になったとみなす時間 |
| `PROBE_TIMEOUT_US` | 0.3 秒 | 見分けの返事を待つ時間 |

`poll()` の間が 0.1 秒以上空いたら (`PAUSE_GAP_US`)、設定メニューなどで X68000 が止められていたとみなし、その間は時間切れを数えません。

返事や `'R'` `'W'` `'w'` が来なかったときは、実行中のコマンドを異常終了にして、見分けからやり直します。あとから届いた返事を、次の読み出しの返事と取り違えないためです。

### ディスクの読み出し (#381)

- X68000 を動かす前 (ホスト版) か、止めている間 (ベアメタル版。設定メニューと同じ一時停止) だけ読みます。始めるのは、X68000 がコマンド、リザルト、シークの割り込み、DMAC のチャネル 0、強制レディのどれの途中でもないときだけです。途中なら、`Fuk` を動かさずにすぐ断ります (X68000 が止まっている間に動かすと、DMAC の渡してこない書き込みを時間切れと取り違えるため)。途中でなければ、FUK の返事や送り残しが終わるのを 1 秒まで待ちます。
- 送るコマンドは SPECIFY (ホスト版だけ)、SENSE DEVICE STATUS、RECALIBRATE、SENSE INTERRUPT STATUS、SEEK、READ ID、READ DATA の 7 つです。`FukReader::allowed()` にないコマンドは送りません。さらに、読んでいる間は `Fuk` が書き込みのコマンドを断ります (DMAC とのつながりを外し、転送バイト数を 0 にするため)。ドライブ制御 (排出) には何も書きません。
- トラックごとに READ ID で書式を確かめ、READ DATA でセクタ 1〜8 を読みます。TC を送れないので、EOT まで読んだ FDC が異常終了 (ST1 の EN だけ) と答えても、データがそろっていれば読めたとみなします。ほかのエラーと、ST2 が 0 でないもの (削除データなど) は、読めないとみなします。
- 終わると、割り込みを引き取り、X68000 が最後に頼んだシリンダへ戻し (分からなければ 0)、ドライブの選択とモーターを X68000 が書いた値に戻します。モーターを戻したあと 0.5 秒待ち、レディの変化の割り込みも引き取ります (戻している途中で FUK が答えなくなったときは引き取らずに終わり、割り込みがあとから X68000 に届くことがあります)。ヘッドを動かす前に失敗したとき (ディスクなしなど) は、ヘッドを動かしません。ヘッドを戻せなかったときは、読んだイメージは使えるので成功のまま、戻せなかったことを結果に書き添えます。このとき (途中で FUK が抜けたときも) は、X68000 がそのドライブの SEEK か RECALIBRATE をするまで、WRITE ID を断ります。WRITE ID は、ヘッドのいるトラックに書くためです。ディスクの出し入れの割り込みは X68000 に残します。
- 途中で FUK が抜けたときなどは、読み出しのために送ったコマンドの結果を X68000 に見せません。

### ベアメタル版のコアの連携

X68000 はコア 1 で動き、USB はコア 0 が扱います。コア 0 の主ループは 1 周に 2 ms 以上かかる (待ち、ネットワーク、SD カード) ので、送受信には使いません。コア 1 とコア 0 の間は、ポートと向きごとのロックのないリング (`platform/fuk_ring.h`) で受け渡します。

- **受信**: 受信の転送を出したままにしておきます。届いたら、コア 0 の USB の割り込みの中でリングに入れ、すぐ次の転送を出します。コア 1 は、ラスタごとと、FDC のレジスタを読み書きしたときにリングを見ます。
- **送信**: コア 1 がリングに入れて、コア 0 にコア間の割り込み (IPI) を送ります。コア 0 は IPI のハンドラの中で送信の転送を出し、送り終わりの割り込みで残りを続けて送ります。
- Machine の状態を変えるのはコア 1 だけです。コア 0 はバイトを運ぶだけです。
- 抜き差しは、コア 0 の主ループが Circle のプラグアンドプレイの処理のあとに見ます。
- 抜いたときは、Circle の xHCI のドライバが装置のスロットを無効にする前に知らせを受けて (`tools/circle_fuk_patch.sh` で足した呼び出し)、それ以上転送を出さないようにします。スロットを無効にしてから USB シリアルのドライバが消えるまでの間に、コア 1 からの頼みで送信の転送を出すと、無効なスロットに出すことになるためです。
- USB の転送が失敗したとき (装置は抜けていない) は、その装置を、抜いて挿し直すまで使いません (FDC のコマンドは「ノットレディ」で終わります)。コントローラは失敗したエンドポイントを止めていて、続けるには装置の側とデータの順番をそろえ直す必要があり、失敗した転送のうち装置に届いた分も分かりません。そのまま続けると、書き込みのデータが重なったり欠けたりしてディスクを壊しうるためです。
- コア 0 がログに出す数 (つながっているか、読み出しの回数など) は、コア 1 が 4 ms に 1 回ほど写しを作って見せます。

### 異常終了したコマンドの記録 (#400)

異常終了で終わったコマンドと、つなぎ直した理由を、ログに 1 行ずつ出します (ベアメタル版はログ、ホスト版は標準エラー出力)。

```
fuk: at 752.123 s: WRITE ID [4d 00 03 08 54 e5] failed, result [40 02 00 00 00 00 03] from the device, select 80, control 01, DMA 32/32, 0 stray, 12 write frames
fuk: at 503.360 s: link lost: no 'w' after the data, 10000 ms, waiting for 'w', command WRITE DATA [45 00 02 01 01 03 08 35 ff], select 80, control 01, DMA 1024/1024, 0 stray, 13 write frames
```

- 1 行目は、`'W'` を送ってデータを受け取ってから書き込み禁止を返す、偽物の装置での例です。`'W'` を送らずに `'w'` を返す装置なら `DMA 0/32` になります。
- 時刻は記録したときのもので、ログの行の時刻より前です。`select` と `control` は、X68000 が最後に $E94007 と $E94005 に書いた値です。
- リザルトを作ったもの: `from the device` は FUK。`changed by a DMA error` は、DMA の異常終了のために pix68k がオーバーランに変えたもの。`made by failCommand` は、つながりが切れたときなど。`made by setResult7` は、FUK に送る前にやめた書き込み (`write cancelled`)、受け付けない書き込み (`write refused`)、つながっていない間 (`not connected`)。
- `DMA` は書き込みのコマンドだけに出す、DMAC から受け取ったバイト数と、コマンドの 1 バイト目を受け取ったときの DMAC の転送バイト数。`stray` は、そのコマンドの間に捨てたバイト。
- `write trace #番号`: WRITE ID から始まるひと続きの書き込みの、WRITE ID、WRITE DATA など書き込みのコマンドと、2 バイトの SENSE INTERRUPT STATUS の、コマンドとリザルト (正常に終わったものも)。先頭の 4 件と最後の 32 件を、書き込みが 10 秒なくなってから出す。間の分は出さない (番号が飛ぶ)。WRITE ID から 120 秒の間は、WRITE DATA だけでも始める。出し終える前に次の書き込みが始まったら、その続きとして扱う (番号も続く)。10 分あたり 16 回分まで。ベアメタル版は、10 秒たつ前に電源を切ると出ない (ホスト版は終わるときに出す)。
- `stray`: 捨てたバイトの種類、値、最後の返事からの時間、そのときの段階と直前のコマンド。種類ごとに先頭の 4 件で、ひと続きの書き込みが始まるか、10 分たつたびに数え直す。ひと続きの書き込みの間のものは、`write trace` と一緒に出す (異常終了とつなぎ直した理由は、すぐに出す)。ためておけるのは先頭の `write trace` と合わせて 64 件。総数は統計の行の `stray bytes`。
- `odd reply`: 余分なバイトを返事として受け取り、ずれたかもしれないもの。要求を送り終える前に届いた返事、書き込みのリザルト (READ ID は US だけ) の US か N がコマンドと合わない、SENSE INTERRUPT STATUS の PCN がシーク先と合わない、コマンドを待つはずのときにリザルトありのステータス、リセットのあとのステータス。値が偶然合えば見つからず、ずれでなくても出ることがある。種類ごとの数え方は `stray` と同じ。
- ディスクの読み出し (#381) のコマンドの異常終了は記録しない。読み出しの間のつなぎ直し、捨てたバイト、ずれた返事には `reading a disk` と書く (`select` は、読み出しが選んだドライブではなく X68000 が書いた値)。
- 記録しないもの (異常終了): SENSE DEVICE STATUS、引き取る割り込みのない SENSE INTERRUPT STATUS、レディの変化、EOT まで読んだ Read の異常終了 (ST1 が EN だけ)。つながっていない間の SEEK と RECALIBRATE の終わり。
- 10 秒あたり、書き込みのコマンド (WRITE ID、WRITE DATA、SCAN など) は 16 件、そのほかは 4 件までです。書き込みと数を分けるので、読めないセクタが続いても、書き込みの記録は残ります。つなぎ直した理由は数えません。
- X68000 を動かすスレッド (コア 1) は固定長の記録をリング (64 件) に積むだけで、文字列にするのは、ログを出すほう (ベアメタル版はコア 0) です。リングに入らない分と上限を超えた分は捨て、その数を統計の行の `events not logged` に出します。

## 既知の制限

次の場合、書いている途中だった書き込みのうち、まだ届いていなかった部分が 0 で埋められて書かれることがあります。起きるのは、pix68k が `'M'` とデータを送っている間 (ふつうは数 ms ですが、送信が詰まれば長くなります) に重なったときです。書き込みは複数のセクタにまたがることがあるので、そのとき書いていたセクタがすべて壊れえます。

- **装置の電源が保たれたまま、USB だけが切れて戻ったとき** (ハブの瞬断、ホストのコントローラのリセット、スリープからの復帰など)。ホスト版でもベアメタル版でも、USB から消えて戻った装置は初めの状態に戻ったとみなし、送り残しを捨てて見分けの `0x00` を送ります。装置がまだ `'M'` のデータを待っていると、その `0x00` がデータとして読まれます。Pico 2 W のファームは、USB が切れたことを知らせる処理を持たず、電源が落ちない限りデータを待ち続けます。pix68k の側からは、この場合と挿し直した場合を見分けられません。X68000 にはノットレディの異常終了を返すので、ソフトウェアが書き直せば正しい内容で上書きされます。
- **`'M'` とデータを送っている途中で pix68k を終了して、起動し直したとき**。起動したときの見分けの `0x00` が、同じようにデータとして読まれます。

また、ホスト版で X68000 が止まっている間 (設定メニューなど) に抜いて挿し直すと、ポートが消えたのを見逃します。読み書きに失敗していたポートは、もう一度抜いて挿し直すまで開きません (ディスクは壊しません)。

## 試験

- `fuk_test`: `Fuk` の単体テスト。見分け、SEEK と SENSE INTERRUPT STATUS、Read (DMA、DMA なし)、Write、DMA を使わない Write を断ること、書き込みの途中のリセットとつなぎ直し、WRITE ID、READ ID、ドライブの状態、強制レディ、時間切れ、抜き差し、リセット。返事が届く前に次の読み出しを送っていないことも確かめます。
- `fuk_test` の `testTrace`、`testDmaAbortEvent`、`testEventThreads` (#400): 書き込みの記録、捨てたバイトの内訳、ずれた返事、DMA の異常終了、積むスレッドと取り出すスレッドを分けたとき。
- `fuk_test` の `testEvents` (#400): 異常終了の記録。書き込み禁止の WRITE ID、断った書き込み、やめた書き込み、件数の上限、記録しないもの、つなぎ直した理由、リングが一杯のとき。
- `fuk_reader_test`: ディスクの読み出しの単体テスト。全バイトの一致、読めないセクタ、別の書式、ディスクなし、出し入れ、中止、抜き差し、時間切れ、X68000 のリセットと、終わったあとの FDC の状態を確かめます。X68000 の読み書きの途中で断ったあとに、その読み書きが最後まで続くことと、ヘッドを戻せなかったあとの WRITE ID を断ることも確かめます。どの場合も、書き込み、排出、転送バイト数を 1 つも送っていないことを見ます。
- `x68k_boot_fuk_read`: `x68k_boot_fuk` と同じことを、47 フレームごとに X68000 を止めてディスクを読み出しながら行います。
- `x68k_boot_fuk`: 偽物の装置に入れた Human68k 3.02 のディスクから起動し、`copy` でファイルを書いて `dir` で確かめます (IPL ROM と起動ディスクがなければ飛ばします)。
- `host_fuk_test`: ホスト版のシリアルポートの口を、pty の先に置いた偽物の装置で確かめます。Windows では、`tests/unit/host_fuk_win_test.cpp` が同じことを名前付きパイプの先に置いた偽物の装置で確かめます。
- `fuk_test` の `testStreamedReadBursty` (#320): X68000 が 1 フレーム分を実時間の 1 ms、4 ms、12 ms で動かしてから休む動かし方をまねます (届いたバイトを受け取るのがフレームの初めに寄る)。装置が 1 バイトずつ送る場合と 64 バイトずつまとめて送る場合のどちらでも、届いた時刻の間隔が保たれることを確かめます。`testStreamedReadFixedLead` は、`fuk_lead=` を決めたときにその遅れで渡し始めることを確かめます。
- `fuk_test` の `testStreamedRead` など (#320): ディスクから読んだ時刻に 1 バイトずつ答える偽物の装置 (R から EOT まで読む) で、最初のバイトがデータの全部届く前に渡ること、TC がリザルトより前に来ること、届いた時刻の間隔が保たれることを確かめます。届いている途中の DMA の異常終了と、残りが来ないときの時間切れも確かめます。
- `x68k_boot --fuk A.xdf --fuk1 B.xdf --fuk-realtime U:C:H:R:割合` (#320): 指定した Read にディスクから読んだ時刻で答える偽物の装置で動かします (割合 (%) だけ、そのセクタを読む時間を長くします)。`--fuk-head` でデータを読み始めにまとめて送る形、`--fuk-one-sector` で最初のセクタで終える形、`--fuk-ports A,B` で偽物の代わりにシリアルポート (実物か `tools/pico_fukemu` の hostsim) につなぎます。

- `circle_fuk_patch_test`: Circle の書き換えが今の Circle に当たることと、書き換える行がなくなったら失敗することを確かめます。

## 手順の出どころ

FUK とのやり取りの手順 (USB の見分け方、バイトの形式、レジスタの対応、コマンドの流れ) は、FUK の動作を再現する Pico 2 用のファームのリポジトリ (j3tm0t0/picoZloader の `fuk` ブランチ、コミット 6424115) にある次のものから取りました。

- `fuk/HOST.md`: エミュレータから FUK を使う手順をまとめた資料
- `fuk/README.md`、`fuk/firmware/src/fdc.c`: ファームの説明とソース (リセットや書き込みの途中の動きは、ここで確かめました)

先読みのしかた、時間の定数、つながっていないときの答え方は、pix68k で決めたものです。

## 実物のふろっぴU君で確かめていないこと

- 実物での動作そのもの。
- リセット (`0x40`) で `'M'` 待ちをやめるか (上の「使っている間の制限」)。やめないと、取り消した書き込みのあとの書き込みが別のセクタに書かれうるので、実物で最初に確かめます。
- シークの間のステータス。pix68k は、コマンドを待っている間に FUK が「コマンドの途中」(RQM と CB が 1、DIO が 0) と答えても、CB を落として返します (コマンドのバイトを全部送り終えているので、コマンドの途中ではないと分かるため)。
- ディスクの読み出し (#381)。偽物の装置と hostsim のほかには、Pi 4 と Pico 2 W のファームの組み合わせで、ドライブ 0 と 1 のディスクを読み、イメージの全バイトが元と一致すること、読み終えたあと X68000 が続きから動くこと、途中の中止、読み出しの途中の再起動、その間にファームが数えた書き込みが 0 回だったことを確かめました。実物のふろっぴU君、Pi 400 と Pi 5 での読み出し、読んでいる間の画面の表示、設定メニューからの再起動は、確かめていません。
- 2DD のディスク、ディスクの入れ替え (`'D'`)、ドライブ 1〜3。
