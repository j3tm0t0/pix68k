# 68060 コアのホスト計測 (astra060)

基準は `e22a910b4f08030b3918bd07c8a56f92b04e2638`。macOS arm64、AppleClang 21.0.0、CMake Release
(`-O3 -DNDEBUG`) で計測した。Pi 5 での計測ではない。ビルドは最大4並列、計測は `nice -n 10` で逐次実行した。
最初のビルドではサンドボックスが nice の優先度設定を拒否したため、以後のビルドと計測は設定できる環境で実行した。
外部の Musashi ソースをビルドしないよう `-DMUSASHI_DIR=` を指定した。

```sh
timeout 600 nice -n 10 cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DMUSASHI_DIR=
timeout 1800 nice -n 10 cmake --build build -j4
cp build/cpu020_bench build/cpu020_bench-baseline
# 変更を適用して再ビルド
# 以下の before / after を交互に3回。ビルドと ctest は先に終える。
timeout 180 nice -n 10 build/cpu020_bench-baseline --cpu 68060 -n 1000
timeout 180 nice -n 10 build/cpu020_bench --cpu 68060 -n 1000
```

既存の `cpu020_bench` は ROM 不要で、256サイクルずつ `run()` を呼ぶ。値はプロセスCPU時間から求める。
命令・データキャッシュは有効、PCR の ESS と分岐キャッシュは無効という既存の設定を使用した。
他プロセスの負荷が高く、CPU時間にもクロックやコア割当の変動が残るため、ホスト命令数とサイクル数も併記する。

## プロファイルと変更

基準版の `--cpu 68060 -n 1500 mix` を `sample <pid> 5` で調べた。3000サンプル中1614 (53.8%) が
`runUntil()` 自身で、残りの大半は MOVE、JSR、DBcc、Bcc などのハンドラ。`fetch32()` は48サンプル (1.6%)。
A0–A7の一律コピー削減、割り込み状態が変わらない間の検査省略、EA別のハンドラ特殊化は基準版にすでにある。

今回の変更:

- データTLBのユーザ／スーパーバイザの選択をSビット変更時に行い、通常の読み書きで配列の先頭の計算を省く。
  SR設定、レジスタ設定、例外、割り込み、リセット、ステート読込後のTLB初期化で選び直す。
- 命令取得と実行ループを軽くする。68060のオペコード取得では常にゼロの68030用サイクル加算の検査を省く。
  32ビット拡張語は同じ命令ページ内だけまとめて読み、インライン展開する。ページをまたぐときやBusに出るときは
  従来どおり2語を順に読み、途中のPC更新、サイクル数、例外を維持する。同時実行の条件判定も、
  相手がない場合やESSが無効な場合を先に判定する順序にした (今回のClangでは命令列は変わらない)。

命令のデコード結果を記憶する変更はない。命令境界のサイクル数・割り込み判定をまとめる変更もない。
機種ごとに全ハンドラを分ける案も試したが、ホスト命令数の改善が約1%以下だったので採用しなかった。

## 結果

各ケース10億命令相当、3回の中央値。ns/命令は小さいほど速い。倍率は変更前のns / 変更後のns。

| ケース | 前 ns/命令 | 後 ns/命令 | 倍率 | 前→後 ホスト命令/命令 | 前→後 ホストサイクル/命令 |
|---|---:|---:|---:|---:|---:|
| siperf | 4.28 | 3.54 | 1.209 | 70.6 → 68.2 | 11.5 → 10.5 |
| copy | 5.94 | 5.96 | 0.997 | 102.2 → 97.7 | 17.7 → 16.5 |
| call | 5.36 | 5.23 | 1.025 | 91.3 → 87.1 | 15.2 → 14.5 |
| mix | 4.81 | 4.24 | 1.134 | 78.7 → 74.8 | 13.4 → 13.0 |

各回のns/命令と、前後6回すべてで一致したチェックサム:

| ケース | 前の3回 | 後の3回 | チェックサム |
|---|---|---|---|
| siperf | 4.93, 3.86, 4.28 | 3.22, 3.61, 3.54 | `ff75b5bd` |
| copy | 7.49, 4.80, 5.94 | 5.96, 5.61, 6.01 | `61d72236` |
| call | 6.42, 5.22, 5.36 | 5.23, 5.03, 5.68 | `634e24fa` |
| mix | 5.00, 4.31, 4.81 | 4.16, 5.11, 4.24 | `af74d8fd` |

ホスト命令数の中央値は全ケースで3.4～5.0%減った。時間はsiperfが約21%、mixが約13%、callが約2.5%の改善、
copyは約0.3%の悪化でほぼ横ばい。負荷によるばらつきが大きいため、これらの時間の倍率をPi 5へ外挿しない。
Pi 5で必要な1.5～2倍は未達。全ケースでサイクル数と、レジスタ・メモリ・サイクル数を含むチェックサムが一致した。

## 検証

境界を含む32ビットフェッチと2回の16ビットフェッチの比較、次ページでのバスエラー、
別のユーザ／スーパーバイザページを温めてからのモード切替を回帰試験に追加した。
既存の68060単体試験には697764件の例外復帰検査と34871オペコードのサイクル分類検査がある。

`timeout 1200 nice -n 10 ctest --test-dir build --output-on-failure -j4 --timeout 120` は、
変更前・変更後とも119件中117件成功、2件スキップ、失敗なし。変更後は144.00秒だった。
スキップは外付けSCSI用の素材がない `x68k_scsi_ex_cdrom` と `x68k_boot_scsi_ex`。
MMU、タイマ割り込み、バス待ち、ステート復元、060turboの起動試験も成功した。

## 次に調べること

- 命令境界のチェックを保ったスレッド化ディスパッチ。実行ループへの呼出し・復帰を減らす。
- PCとサイクル数など頻繁に使う状態のレジスタ保持。Bus呼出し、例外、外部コールバックの前には正確に反映する。
- TLBのタグとホストポインタの配置。Cortex-A76の実測でロード依存とキャッシュ使用量を評価する。
