# リリースの説明

公開リポジトリ (j3tm0t0/pix68k) の Release の説明の本文を、版ごとに `<タグ>.md` (例: `v0.2.0.md`) に書く。

- タグを push すると、`.github/workflows/release.yml` がこのファイルを読み、ソースの場所と SHA256SUMS の文を後ろに足して Release の説明にする。
- タグを付けるコミットにこのファイルがない (空か、空白だけのときも同じ) と、workflow は zip のビルドの前に、Release を作らずに失敗する。公開リポジトリは immutable releases なので、
  公開したあとは添付のファイルを変えられない。説明はタグを付ける前に書いてコミットしておく。
- 添付のファイル (zip、pix68kcli の 7 つ、SHA256SUMS) の一覧と SHA-256 は workflow が作るので、ここには書かない。

## beta (人に試してもらう版)

- タグを `v<次の版>-beta.<番号>` (例: `v0.2.3-beta.1`) にすると、release.yml は pre-release で、Latest にせずに出す。正式な版の Latest は動かない。
- `docs/releases/<タグ>.md` はなくてよい。なければ説明の本文を自動で作る: 試験用の版であること、タグのメッセージ、前のタグからのコミットの一覧。元にした開発用のリポジトリのコミットは、注釈付きのタグ (`git tag -a`) のメッセージに書く。ファイルがあればそちらを使う。
- 公開リポジトリは immutable releases なので、同じ beta を出し直すことはできない。直したら番号を上げる (`-beta.2`)。
- `-beta` を含むのに形が違うタグ (`v0.2.3-beta`、`v0.2.3-beta1` など) と、`-beta` 以外の付け足し (`v0.2.3-rc1` など) は止める。
- 形が違って止まったタグ (と、止まった beta のタグ) は消す (`git push --delete origin <タグ>`)。残すと、次の beta の説明の「前のタグ」に選ばれることがある (`v` と数字で始まるタグだけを見る)。
