## v0.2.4 からの変更

### 直したこと
- VGMDRV など、ユーザモードのまま `$EC0000`〜`$ECFFFF` (拡張ボードなどの番地) を読み書きするソフトが、バスエラーで止まるのを直した ([expansion.md](https://github.com/j3tm0t0/pix68k/blob/v0.2.5/docs/expansion.md))。この範囲にあるまーきゅりーゆにっと (`mercury=on`) などのボードを、ユーザモードからも使える。

### 画面の明るさ
- ソフトがシステムポート (`$E8E001`) で変える明るさ (コントラスト) を、画面に反映する。x68k-xvi さんの提案と PR をもとにした ([video.md](https://github.com/j3tm0t0/pix68k/blob/v0.2.5/docs/video.md))。通常の 14 では、これまでと同じ色になる。14 と 15 の差、途中の明るさ、0 で真っ黒になるかが、X68000 の実機と同じかは確かめていない。
- Human68k の終了後は、画面が黒いままになる (リセットすると戻る)。
- この版で保存したステートは、v0.2.4 までの版では読めない。v0.2.4 のステートは、この版で読める。

### ふろっぴU君 (FUK、ベータ)
- 異常終了したコマンド (一部を除く) と、つなぎ直した理由をログに出す。フォーマットの間のコマンドと結果も、先頭の 4 件と最後の 32 件を出す (ベアメタル版は `/log`。[fuk.md](https://github.com/j3tm0t0/pix68k/blob/v0.2.5/docs/fuk.md))。原因を調べるためのもので、読み書きの動作は変えていないが、この変更のあと、実物の FUK での動作と、書き込みは確かめていない。

### そのほか
- テスト画面 (X68000 を起動していないとき。ベアメタル版の全機種) で、押しているキーも修飾キーも前のレポートと同じなら、キーの行 (`key: mod=...`) をログに出さない。
- CPU の試験データを取ってくるスクリプト (`tools/fetch_sst.sh`) が、GitHub の API を使わないようにした (ソースからビルドする人向け)。

### 更新のしかた
- v0.2.4 のカーネルからは `pix68kcli update --no-tryboot` で更新できるはずだが、`update` そのものは実機で試していない (Pi 400 で、同じ順に要求を送るスクリプトと `--rollback` を確かめただけ)。心配なら zip から手で入れる。**起動しなければ、SD カードをパソコンに入れて `config.txt` の `kernel=` を戻す** ([pix68kcli の README](https://github.com/j3tm0t0/pix68k/blob/v0.2.5/tools/pix68kcli/README.md))。

### 既知の問題
- 日本語キーボードの Pi 400 で英語版と判定され、半角/全角キーを押すと `¥` が出ることがある。`pix68k.cfg` に `keyboard=pi400jp` と書いて起動し直すと、半角/全角キーが全角として働く (日本語版の Pi 400 と v0.2.4 で確かめた)。本体のほかのキーの動作は、どちらの設定でも同じ。外付けのキーボードにも Pi 400 の本体と同じキーの置き換えをするようになる ([keyboard.md](https://github.com/j3tm0t0/pix68k/blob/v0.2.5/docs/keyboard.md))。
- v0.2.4 の既知の問題のうち、Pi 400 に正式には対応していないことと、ミキサーのキーは、この版でも同じ ([v0.2.4 の説明](https://github.com/j3tm0t0/pix68k/releases/tag/v0.2.4))。

## Changes since v0.2.4 (English)

### Fixed
- Programs that read and write `$EC0000`-`$ECFFFF` (the addresses of expansion boards and the like) in user mode, such as VGMDRV, no longer stop with a bus error ([expansion.md](https://github.com/j3tm0t0/pix68k/blob/v0.2.5/docs/expansion.md); the linked documents are in Japanese). Boards in this range, such as the Mercury Unit (`mercury=on`), can also be used from user mode.

### Screen brightness
- The brightness (contrast) that software sets through the system port (`$E8E001`) is now applied to the screen. This is based on a proposal and a PR by x68k-xvi ([video.md](https://github.com/j3tm0t0/pix68k/blob/v0.2.5/docs/video.md)). At the usual value of 14, the colors are the same as before. Whether the difference between 14 and 15, the levels in between, and full black at 0 match a real X68000 has not been checked.
- After Human68k shuts down, the screen stays black (a reset brings it back).
- States saved with this version cannot be loaded with v0.2.4 or earlier. States from v0.2.4 can be loaded with this version.

### Floppy-U-kun (FUK, beta)
- The log now shows commands that ended abnormally (with some exceptions) and why pix68k reconnected to the FUK. It also shows the first 4 and last 32 commands and results of a format (`/log` on the bare-metal build; [fuk.md](https://github.com/j3tm0t0/pix68k/blob/v0.2.5/docs/fuk.md)). This is for finding causes; it does not change how reading and writing work, but since this change, operation with a real FUK and writing (with any device) have not been tested.

### Others
- On the test screen (shown when the X68000 is not running; all bare-metal models), a key line (`key: mod=...`) is no longer logged when the pressed keys and modifiers are the same as in the previous report.
- The script that fetches the CPU test data (`tools/fetch_sst.sh`) no longer uses the GitHub API (for those who build from source).

### How to update
- From the v0.2.4 kernel, `pix68kcli update --no-tryboot` should work, but `update` itself has not been tried on real hardware (only a script that sends the same requests in the same order, and `--rollback`, on a Pi 400). If in doubt, install by hand from the zip. **If it does not boot, put the SD card in a PC and change `kernel=` in `config.txt` back** ([pix68kcli README](https://github.com/j3tm0t0/pix68k/blob/v0.2.5/tools/pix68kcli/README.md)).

### Known issues
- A Pi 400 with a Japanese keyboard may be detected as the English version, and the Hankaku/Zenkaku key may type `¥`. With `keyboard=pi400jp` in `pix68k.cfg` and a restart, the key works as Zenkaku (tested on a Japanese Pi 400 with v0.2.4). The other built-in keys behave the same with either layout setting. The key mapping of the Pi 400 then also applies to external keyboards ([keyboard.md](https://github.com/j3tm0t0/pix68k/blob/v0.2.5/docs/keyboard.md)).
- Of the known issues of v0.2.4, the lack of official Pi 400 support and the mixer key also apply to this version ([v0.2.4 notes](https://github.com/j3tm0t0/pix68k/releases/tag/v0.2.4)).
