## v0.1.0 からの変更

### 画面
- 画面の効果と拡大の設定を `video_filter=` と `video_scale=` の 2 つにまとめた。`pix68k.cfg` か、設定メニューの Display のページ (Scale、Scanlines、Curve、Mask、Bezel) で選ぶ。ホスト版 (SDL2) にも同じ設定がある (枠は除く)。
  - `video_filter=` は掛ける効果を `,` で区切って並べる (例: `video_filter = scanline,curve,mask`)。`none` か空なら効果なし (既定)。
    - `scanline`: スキャンライン (縦 2 倍以上に拡大したとき)
    - `curve`: 画面をたる型にゆがめ、四隅を暗くする
    - `mask`: アパーチャーグリルの縦じまを付け、横に少しにじませる
    - `cz-600de` / `cz-600db`: 画面のまわりにブラウン管のモニタの枠の絵 (グレー / 黒) を出し、X68000 の画面を枠のガラスの部分 (1160x870、4:3) に写す。どちらか 1 つを選ぶ (例: `video_filter = scanline,curve,cz-600db`)。`scanline`、`curve`、`mask` はガラスの中の絵に掛かる。枠を使う間は、`video_scale=` の値 (`off` も) によらず、ガラスの部分いっぱいに写す。ベアメタル版だけで、フレームバッファが 1920x1080 で、X68000 の画面がガラスの部分に入るときに出る (ほかの解像度、768x1024 のようにガラスより大きい画面、絵のファイルがないときは、枠なしで `video_scale=` のとおりに出し、ログに理由を出す)。枠の絵 (`pix68k/bezel-cz-600de.bin`、`pix68k/bezel-cz-600db.bin`) は zip に入っている。絵はスクリプト (`tools/bezel_cz600d.py`) で描いたもので、メーカーのロゴや製品名の文字はない
  - `video_scale=` は X68000 の画面の拡大のしかた。
    - `off`: 拡大しない
    - `integer`: 整数倍 (ベアメタル版の既定)
    - `aspect`: 横を X68000 のモニタと同じ 4:3 にして、表示の高さいっぱいに拡大する (1920x1080 なら 1440x1080。ホスト版の既定)
    - `full`: 表示全体に引き伸ばす
  - 2 つは自由に組み合わせられる。ただし Raspberry Pi 3 では、`curve` は選べない。`full` と `mask` の組み合わせも選べない (1 フレームの時間に収まらないため。`pix68k.cfg` に書いてあれば外して、ログに出す)。
  - ホスト版の既定の出し方が変わった。これまではウィンドウに入る最大の 3:2 に引き伸ばしていたが、既定の `aspect` ではウィンドウに入る最大の 4:3 にする。ウィンドウいっぱいに出すなら `video_scale=full` にする。
  - ベアメタル版は、v0.1.0 の `scale=` と `scanline=` を、v0.1.0 と同じ見た目になるように読み替え、ログに警告を出す (`scale=auto` → `video_scale=integer`、`scale=off` → `video_scale=off`、`scanline=on` → `video_filter` に `scanline`)。設定メニューで保存すると、新しい `video_scale=` と `video_filter=` で書く。ホスト版は、v0.1.0 のホスト版と同じく `scale=` と `scanline=` を読まない (警告も、保存での書き直しもしない)。
- 画面の右上の数字 (`osd=`) に、ネットワークの IP アドレスを出す。`net=on` でアドレスが決まっているときだけ出す。IP アドレスがいつも見えるように、ベアメタル版は余白が足りなければ `osd=on` でも X68000 の画面に重ねる (これまで重ねるのは `osd=fps` のときだけだった)。
- 左上のメッセージ (`POST /message`、ホスト版の `--message`) を 1 行半角 10 桁で折り返す。4 行に入りきらなければ最後を「…」にする。

### 起動
- 起動の組み合わせ: `/pix68k/pix68k-<名前>.cfg` を置くと、起動時に HDMI に一覧が出て、カーソルキーかゲームパッドで選べる。何も押さなければ `profile_wait=` 秒 (既定 5) で前回のものを使う。ファイルの 1 行目を `#` で始めると、その残りを一覧に出す名前にする。
- `POST /reboot?profile=<名前>` で、`pix68k.cfg` を書き換えずに、その組み合わせで再起動する。
- `autotype=` (組み合わせのファイルにも書ける) で、X68000 が動き出して `autotype_wait=` 秒 (既定 10) たったらキーを打たせられる。

### pix68kcli
- HTTP で操作するためのコマンド `pix68kcli` を足した (`tools/pix68kcli`、Go)。curl で token のヘッダを毎回書く代わりに使う。状態、ログ (`-f` で追いかける)、画面の PNG での保存、再起動 (組み合わせを選べる)、キーの入力、メッセージ、SD カードのファイルの読み書きができる。宛先と token は設定ファイルに書く。使い方は `tools/pix68kcli/README.md` にある。
- このリリースに 7 種類のバイナリを付けた。

| OS | ファイル |
| --- | --- |
| macOS (Apple シリコン / Intel) | `pix68kcli-darwin-arm64` / `pix68kcli-darwin-amd64` |
| Linux (arm64 / Raspberry Pi OS 32 ビット / x86-64) | `pix68kcli-linux-arm64` / `pix68kcli-linux-armv7` / `pix68kcli-linux-amd64` |
| Windows (x86-64 / arm64) | `pix68kcli-windows-amd64.exe` / `pix68kcli-windows-arm64.exe` |

  macOS と Linux (arm64、x86-64) では、Homebrew で `brew install j3tm0t0/tap/pix68kcli` として入れられる。この場合は、下の quarantine と実行の許可の手当ては要らない。

  バイナリを直接落とした場合: 署名していないので、macOS では `xattr -d com.apple.quarantine <ファイル>` が要る。macOS と Linux では `chmod +x <ファイル>` も要る。

  macOS では、どちらの入れ方でも、ターミナルのアプリに「ローカルネットワーク」の許可が要る (システム設定 > プライバシーとセキュリティ > ローカルネットワーク)。

### 060turbo と X68030
- 68060 の命令を実行するループを短くした。Pi 5 で 060turbo を 75MHz にした設定で、OutRun (X68000 への移植版 CBX68) のデモの重い場面で、エミュレータが 1 フレームの処理に使う時間が 2〜3% 減った。68060 のサイクル数の数え方と、命令の実行結果は変わらない。
- X68030 と 060turbo で、スプライトの読み書きの時間を I/O と同じ 1.6 マイクロ秒の区切りにそろえるのを、既定ではやめた。そろえると OutRun でスプライトが崩れていた。前の動きに戻すには `bus_sync_sprite=on` を書く。

### 音
- エミュレータが実時間に間に合わない間は、音を途切れさせずに、最大 25% 遅く鳴らす。OPM、ADPCM などは遅くなった分だけ低く鳴る (25% で約 5 半音)。MIDI の音源 (MT-32、SF2、SC-55) は音の高さが変わらず、演奏が遅くなるだけなので、OPM と MIDI を一緒に鳴らす曲では、その間だけ音の高さがずれる。エミュレータの速さが実時間の 75% を下回ると、これまでどおり途切れる。

### DMA
- DMAC のオートリクエストの最大速度の転送は、CCR に書いて転送を始めたときに、その場で最後まで転送するようにした。実機ではこの転送の間 CPU が止まるが、これまでは転送を後回しにしていたので、その間に CPU が次の転送のレジスタを書き換えると、別のデータが送られていた。これで、グラディウス II (FD 版) のタイトルのロゴと、プレイ中のスプライトのパターンが別のものになるのが直った。X68030 の内蔵 SCSI の DMA の転送も、始めたところで終わるようになる。

## Changes since v0.1.0 (English)

### Display
- Display effects and scaling are now two settings, `video_filter=` and `video_scale=`, set in `pix68k.cfg` or on the Display page of the settings menu (Scale, Scanlines, Curve, Mask, Bezel). The host (SDL2) build has the same settings (except the bezel).
  - `video_filter=` lists the effects to apply, separated by `,` (e.g. `video_filter = scanline,curve,mask`); `none` or empty means no effect (default). `scanline`: scanlines (when scaled 2x or more vertically). `curve`: barrel distortion and darkened corners. `mask`: aperture grille stripes and slight horizontal blur. `cz-600de` / `cz-600db`: draw a CRT monitor bezel (gray / black) around the screen and show the X68000 screen in its glass area (1160x870, 4:3); pick one (e.g. `video_filter = scanline,curve,cz-600db`). `scanline`, `curve` and `mask` apply to the picture inside the glass. While the bezel is used, the screen fills the glass area regardless of `video_scale=` (including `off`). Bare-metal build only, with a 1920x1080 frame buffer and an X68000 screen that fits in the glass (otherwise, e.g. for other resolutions, screens larger than the glass such as 768x1024, or a missing image file, the screen is shown without the bezel as `video_scale=` says, and the log says why). The bezel images (`pix68k/bezel-cz-600de.bin`, `pix68k/bezel-cz-600db.bin`) are in the zip; they are drawn by a script (`tools/bezel_cz600d.py`) and contain no manufacturer logos or product names.
  - `video_scale=` sets how the X68000 screen is scaled: `off` (no scaling), `integer` (integer multiples, default on bare metal), `aspect` (4:3 like the X68000 monitor, full display height; 1440x1080 on 1920x1080; default in the host build), `full` (stretch to the whole display).
  - The two can be combined freely, except that on Raspberry Pi 3 `curve`, and `full` together with `mask`, are not available (they do not fit in the frame time; if set in `pix68k.cfg` they are dropped with a log message).
  - The host build's default output changed: it used to stretch to the largest 3:2 area in the window; the default `aspect` now uses the largest 4:3 area. Use `video_scale=full` to fill the window.
  - The bare-metal build still reads the v0.1.0 settings `scale=` and `scanline=` and maps them to look the same as in v0.1.0, with a warning in the log (`scale=auto` → `video_scale=integer`, `scale=off` → `video_scale=off`, `scanline=on` → `scanline` in `video_filter`). Saving from the settings menu writes the new two settings. The host build, like the v0.1.0 host build, does not read `scale=` and `scanline=` (no warning, and saving does not rewrite them).
- The on-screen numbers at the top right (`osd=`) now include the network IP address when `net=on` and an address is assigned. To keep the address visible, the bare-metal build now overlays them on the X68000 screen even with `osd=on` when there is not enough margin (previously only with `osd=fps`).
- The top-left message (`POST /message`, `--message` in the host build) now wraps at 10 half-width columns per line, and ends with "…" when it does not fit in 4 lines.

### Boot profiles
- Put `/pix68k/pix68k-<name>.cfg` files on the SD card to get a boot menu on HDMI. Choose with the cursor keys or a gamepad; after `profile_wait=` seconds (default 5) without input, the previous choice is used. A first line starting with `#` gives the name shown in the menu.
- `POST /reboot?profile=<name>` reboots with that profile without changing `pix68k.cfg`.
- `autotype=` (also usable in a profile) types keys `autotype_wait=` seconds (default 10) after the X68000 starts.

### pix68kcli
- New command-line tool `pix68kcli` (`tools/pix68kcli`, Go) for the HTTP API, instead of writing the token header for curl every time. It shows the status, follows the log (`-f`), saves the screen as PNG, reboots (optionally with a profile), types keys, shows messages, and reads and writes files on the SD card. Targets and tokens go in a config file; see `tools/pix68kcli/README.md`.
- Seven binaries are attached: macOS (arm64, amd64), Linux (arm64, armv7 for 32-bit Raspberry Pi OS, amd64) and Windows (amd64, arm64). On macOS and Linux (arm64, x86-64) you can install it with Homebrew: `brew install j3tm0t0/tap/pix68kcli` (no quarantine or permission steps needed). If you download a binary directly: it is not signed, so on macOS run `xattr -d com.apple.quarantine <file>`, and on macOS and Linux run `chmod +x <file>`. On macOS, with either method, allow your terminal app under System Settings > Privacy & Security > Local Network.

### 060turbo and X68030
- Shorter 68060 instruction loop. On a Pi 5 with 060turbo set to 75MHz, the emulator's time per frame in heavy scenes of the OutRun demo (CBX68, an X68000 port) dropped by 2-3%. 68060 cycle counting and results are unchanged.
- On X68030 and 060turbo, sprite accesses are no longer aligned to the 1.6 µs I/O slots by default (this broke sprites in OutRun). Use `bus_sync_sprite=on` for the old behavior.

### Sound
- While the emulator cannot keep up with real time, sound now plays up to 25% slower instead of dropping out. OPM, ADPCM and similar sources play lower by the same amount (about 5 semitones at 25%); MIDI synths (MT-32, SF2, SC-55) keep their pitch and only play slower, so songs that use OPM and MIDI together go out of tune during that time. Below 75% of real time it still drops out as before.

### DMA
- DMAC auto-request transfers at maximum rate now complete within the write to CCR that starts them. On real hardware the CPU is stopped during such a transfer; previously the transfer was deferred, so if the CPU rewrote the registers for the next transfer in the meantime, the wrong data was sent. This fixes the title logo and the sprite patterns during play in Gradius II (floppy version). DMA transfers of the X68030 built-in SCSI also complete at the start write now.
