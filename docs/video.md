# 画面の合成

テキスト、グラフィック、スプライトの重ね方、透明なドット、特殊プライオリティと半透明の決まり。

テキスト、グラフィック、スプライト / BG の重ね合わせは `src/x68k/render.cpp` で 1 ラスタずつ行う。

根拠は「Inside X68000」(桑野雅彦、ソフトバンク、1992 年) の画面制御の章。グラフィックは、本のコラム
「グラフィックページ間プライオリティ制御のからくり」のとおり、4 ビットずつの 4 つのブロックを R1 ($E82500) の
GP0〜GP3 で優先順位に割り当て、色モードで組み合わせる作りにしている (標準でない設定でも、その作りのとおりに出る)。
本に書かれていない動きは、ほかの資料とゲームの画面、書き直す前の版の出力との比較から決めた。決めたことと理由は
`render.cpp` の先頭の注釈にまとめてある。実機で測ったデータはない。

## 透明なドットと重なり

- テキストとスプライト + BG はパレットが 1 つなので、パレットを引く前に 1 つの色コードにまとめる (優先順位の高いほうの
  色コードが 0 でなければそれ、0 なら低いほう)。スプライト + BG は、パターンのドットが 0 の所が色コード 0
  (BG のブロックやスプライトの色コードの上位 4 ビットが 0 でなくても、上位 4 ビットだけの色コードにはしない)
- まとめた色コードでテキストパレットを引く。その色コードを出した画面がグラフィックより手前なら、色が $0000 で
  なければその色、$0000 ならグラフィックの色を出す。グラフィックより奥なら、グラフィックの色が $0000 でなければ
  グラフィックの色、$0000 ならテキストパレットを引いた色を出す
- 色が $0000 のドットが透明。グラフィックは色コードによらない (グラフィックパレット 0 が $0000 でなければ、
  色コード 0 の所も透明でない)
- どの画面も透明な所には、テキストパレット 0 の色が出る
- テキストもスプライトもグラフィックより手前にあるとき、テキストパレット 0 が $0000 でなければグラフィックは見えない

色が $0000 で透明になることは Seafy 氏の「CRTC の設定 その他」(1993 年) による。テキストパレット 0 の扱いは、
悪魔城ドラキュラのパレットの使い方からの推測 (注釈に書いた)。

## 特殊プライオリティと半透明 (ビデオコントローラ R2、$E82600 の上位バイト)

| ビット | 名前 | 意味 | pix68k |
|---|---|---|---|
| 15 | Ys | ビデオカット | 何もしない (ビデオ画像の入力がない) |
| 14 | AH | テキストパレット 0 との半透明 | ほかのビットによらず、領域のドットをテキストパレット 0 の色と混ぜる |
| 13 | VHT | ビデオ画像との半透明 | 何もしない (ビデオ画像の入力がない) |
| 12 | EXON | 特殊プライオリティ / 半透明を有効にする | bit10 も 1 のときに働く |
| 11 | H/P | 0 = 特殊プライオリティ、1 = 半透明 | |
| 10 | B/P | 1 = ベースページの最下位ビットで領域を指定する | 0 のとき (本では未定義) は、bit12 の機能を行わない |
| 9 | G/G | 半透明: セカンドページと | |
| 8 | G/T | 半透明: テキスト / スプライトと | |

ビットの名前は Data Crystal の X68k:IOMAP のもの。

- ベースページは、グラフィックの一番手前のページ (16 色なら GD0、256 色なら GD1:GD0、65536 色と実画面 1024x1024 は
  画面全体)。そのデータの最下位ビットが 1 のドットが領域。機能が働いている間、ベースページは最下位ビットを 0 にした
  色コードで表示する (特殊プライオリティでも同じとした)
- 混ぜ方は本のとおり: RGB の 5 ビットずつを足して 1 ビット右にずらす (端数は捨てる)。輝度ビットは相手のもの
- 半透明: G/G ならセカンドページ (16 色は GD1、256 色は奥のページ) の色と混ぜる。セカンドページの色コードも
  最下位ビットを無視し、グラフィックパレットの奇数番の色を使う (Inside X68000 p.209 図 30)。G/T なら、
  テキスト / スプライトがグラフィックより奥のときに、その色と混ぜる。両方ならセカンドページ、テキスト / スプライトの順に混ぜる。
  グラフィックより手前のテキスト / スプライトは、混ぜた結果の上に重なる
- 特殊プライオリティ: 領域のドットを、テキストやスプライトより手前に出す

本に書かれていない場合の扱い (最下位ビットを 0 にすると 0 になるドットなど) は
`render.cpp` の先頭の注釈にある。

画面の合成を別のコアで行うとき (ベアメタル版のコア 2、`--render-thread`) も、レジスタへの書き込みは記録を通して写しに
届くので、同じ規則で描く。試験は `video_test` (本の説明から作った期待値と、注釈の決まり)。

TS-6BGA 互換の仮想フレームバッファを Raspberry Pi 4 / 5 の第2 HDMI に出す機能は
[TS-6BGA](ts6bga.md) を参照。

## コントラスト (システムポート $E8E001 の下位 4 ビット)

合成したドットの R、G、B に、それぞれ min(コントラスト, 14) / 14 を掛けて四捨五入する。
倍率は 1/256 刻みに丸めてから掛ける (8 ビットの掛け算で済ませ、直線でないと分かったときも表の値を変えるだけにするため。
丸めずに計算した値との差は、0〜255 の値で 1 まで)。重ね方、透明、半透明の計算には影響しない。
ラインを描くときの値を使うので、フレームの途中で変えると、次に描くラインから変わる。メニューと OSD の明るさは変わらない。

決めたこと (2026-11-25):

- 14 を 1 倍にする。68000 の IPL ROM と Human68k は、ふだん 14 を書く。14 で、コントラストを反映する前の pix68k と同じ色になる
- RESET 命令では値を変えない。電源投入とリセットボタンでは 14 にする
- 版 21 までのステートの 0 は 14 として読む

実機で確かめていないこと (決めたとおりかどうか、資料にない):

- 14 と 15 の明るさの差 (今は同じ)
- 明るさが値に比例するか (今は直線)
- 0 で真っ黒になるか (今は真っ黒)

実機の結果で直すときは、`src/x68k/render.cpp` の `contrastGain()` を変える。

Human68k は電源を切る前にコントラストを 0 にする。pix68k は電源 OFF の書き込み ($E8E00F) では止まらないので、そのあとは
黒い画面のままになる。リセットすると戻る。
